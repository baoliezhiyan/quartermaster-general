# PPO 训练

双击 [启动PPO训练.cmd](启动PPO训练.cmd)，输入目标轮数。每轮是 10 次更新，每次更新完整采集 40 局；程序先完成 A 的全部轮次，再完成 B 的全部轮次。默认 8 个环境共享一份 GPU 模型。不要在已有实验进行中切换源码或规则。

终端会显示轮次、每次更新已完成的完整对局数（例如 `28/40`）和已用秒数。每轮结束后只额外生成一局该轮模型控制双方、每步选择概率最高合法动作的对局记录；对局随机事件仍由独立种子决定。不运行训练前或每 10 次更新后的固定对手评估。完整损失、资源及速度指标写在 `.state/A/training-report.json`、`.state/B/training-report.json`，不会逐条刷在终端。

轮次边界会重新启动训练进程、8 个环境和模型；完成一轮还需生成并校验一份完整回放。训练进程启动和回放导出可能使轮次边界比两次并行更新之间的间隔更长。

此文件夹内：

| 位置 | 内容 |
| --- | --- |
| `启动PPO训练.cmd` | 双击入口；自动检查本地环境、构建当前规则、询问轮数 |
| `A/第001轮/` | A 第 1 轮的 `模型.pt` 和 `AI训练记录.jsonl` |
| `B/第001轮/` | B 第 1 轮的同两种文件 |
| `.runtime/` | 本机复制的 Node/pnpm，以及复用本机 PyTorch 的 Python 环境 |
| `.state/A/`、`.state/B/` | 本接口版本的续训检查点与训练指标报告 |
| `.trajectory-temp/` | 每次更新的临时二进制轨迹；成功保存检查点和报告后自动删除，不是训练结果 |
| `归档/A-20261002-截至第004轮/` | 旧 A 实验第 1～4 轮模型、记录及原续训状态；只读留存，新实验不从这里续训 |

轨迹采用有限内存缓冲分块写盘，更新时按打乱后的当前小批次读取；详细格式、上限、短测和内存指标见 [轨迹存储说明](../docs/training/PPO轨迹磁盘存储-20261002.md)。异常退出后会自动清理超过 24 小时且所属进程已结束的轨迹目录；需要单独检查清理时可在项目根目录运行 `python scripts/ppo_trajectory.py --cleanup-stale`。这项修改不改变每批 40 局、每轮 10 次更新及现有模型的观察/动作编码。

当前接口采用观察 v5、动作 v4、编码 v5 与训练奖励 `repeated-basic-build-v1`。基本建设候选现在把原地重复标记传入网络；能确认存在有效替代建设时，完整的无效重复建设额外记训练奖励 -0.01。旧 A 第 1～4 轮模型和续训状态已归档，入口将从空的 A/B 当前结果目录启动新实验，不会从归档自动恢复。旧权重只能经单独的迁移初始化程序使用，不能冒充可恢复检查点。细节和诊断见 [第一阶段报告](../docs/training/PPO重复建设第一阶段-20261002.md)。`.runtime`、实验结果不上传 Git。第一次启动准备环境可能需要几分钟；之后会复用。已有全局 `pnpm` 不是必需的。训练前仍检查 CUDA，避免意外在 CPU 上跑长期任务。

只验证启动而不开始训练，可以在此目录的终端运行：

```cmd
启动PPO训练.cmd --rounds 1 --dry-run
```

当前使用方式、回放格式和恢复边界见 [PPO 轮次训练启动说明](../docs/training/PPO训练轮次启动说明.md)。
