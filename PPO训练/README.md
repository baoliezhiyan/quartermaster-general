# PPO 训练

双击 [启动PPO训练.cmd](启动PPO训练.cmd)，输入目标轮数。每轮是 10 次更新，每次更新完整采集 40 局；程序先完成 A 的全部轮次，再完成 B 的全部轮次。默认 10 个环境共享一份 GPU 模型。不要在已有实验进行中切换源码或规则。

终端会显示轮次、每次更新已完成的完整对局数（例如 `28/40`）和已用秒数。每轮结束后只额外生成一局该轮模型控制双方的对局记录，不运行训练前或每 10 次更新后的固定对手评估。完整损失、资源及速度指标写在 `.state/A/training-report.json`、`.state/B/training-report.json`，不会逐条刷在终端。

轮次边界会重新启动训练进程、10 个环境和模型；完成一轮还需生成并校验一份完整回放。训练进程启动和回放导出可能使轮次边界比两次并行更新之间的间隔更长。

此文件夹内：

| 位置 | 内容 |
| --- | --- |
| `启动PPO训练.cmd` | 双击入口；自动检查本地环境、构建当前规则、询问轮数 |
| `A/第001轮/` | A 第 1 轮的 `模型.pt` 和 `AI训练记录.jsonl` |
| `B/第001轮/` | B 第 1 轮的同两种文件 |
| `.runtime/` | 本机复制的 Node/pnpm，以及复用本机 PyTorch 的 Python 环境 |
| `.state/A/`、`.state/B/` | 续训检查点与训练指标报告 |

`.runtime`、`.state` 和 A/B 结果不上传 Git。第一次启动准备环境可能需要几分钟；之后会复用。已有全局 `pnpm` 不是必需的。训练前仍检查 CUDA，避免意外在 CPU 上跑长期任务。

只验证启动而不开始训练，可以在此目录的终端运行：

```cmd
启动PPO训练.cmd --rounds 1 --dry-run
```

当前使用方式、回放格式和恢复边界见 [PPO 轮次训练启动说明](../docs/training/PPO训练轮次启动说明.md)。
