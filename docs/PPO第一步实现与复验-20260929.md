# PPO 第一步实现与复验

> 历史首版记录。独立验收指出的缺陷已另行修正；当前实现及检查点见《PPO第一步独立验收修正复验-20260929.md》。本文中的旧检查点因编码 schema 升级不能用于继续训练。

日期：2026-09-29。实施依据为用户提供的《战场军需官PPO第一步实施方案-v0.3.md》。本轮目标是证明事件课程、A/B 资源开放、按国家轨迹和 PPO 更新能在无界面的训练场内贯通；一次更新不构成策略强度结论。

## 交付接口

- `src/training/ppoArena.ts`：复用正式规则引擎的无界面竞技场；`reset/observe/step/truncate/exportSnapshot/fromSnapshot`。决策按来源牌、预承诺目标、引擎后续选择分节点提交。`episodeId/gameId/decisionId/revision` 共同校验动作，旧动作拒绝且不改变状态。
- `src/core/trainingCourse.ts`：固定 58 个事件 ID，德国 12、英国 13、日本 0、苏联 10、意大利 10、美国 13；排除 `special_227`。四基本牌有限资源采用平衡后数量，意大利建设海军 5、发起海战 3，平衡模式的陆军兵模 5。
- 训练覆盖仅在 `trainingCourse` 存在时生效：百团大战、湘西会战不再有付基本牌洗回分支；武器援助保留额外出牌但不摸牌。正式游戏卡牌效果未改。
- A：剩余资源全部开放。B：非基本牌按 `min(N,max(6,ceil(0.6N)))` 抽样，四类基本牌按剩余 1/2/3/≥4 的 0.4/0.7/0.9/1 概率独立开放。首回合使用初始化结果，以后每次本国回合开始刷新；开放集合不限制随机费用与强制弃牌。开放、随机弃牌、策略采样使用不同随机流。
- `scripts/ppo-arena-server.mjs`：逐行 JSON 请求/响应。`reset` 返回静态地图和 schema，`step` 返回下一决策、双方分差变化、已经结束的国家回合数、自然终局/截断。`--log` 保存带“AI训练记录”头的每局操作记录，`trace=full` 会额外保存前后单位、公开日志和规则事件，供以后做可视化。
- `scripts/ppo_train.py`：共享六座位网络、合法候选掩码、按国家轨迹、势函数塑形、按游戏时间衰减的 GAE、PPO 裁剪更新、A/B 独立训练、冻结加权合法动作对手的跨课程评估、检查点与恢复。

## 网络与计算

局势输入 5966 维，候选输入 2337 维，参数量 **1,975,042**。参数量高于方案预估 50–150 万，主要因为每个输入都保留至多 32 个有序效果槽；不截断后半张牌。局势分支 `5966→256→256`，候选分支 `2337→128`，拼接后策略头 `384→128→1`，价值头 `256→128→1`。策略末层小正交初始化；价值末层零初始化。合法候选采用掩码 softmax，等价基本牌副本合并为一个来源选择，数量仍在观察中。

每次自然终局给胜方阵营 +1、负方 −1；非终局 `Φ=0.3·clip(阵营分差/30,−1,1)`，终局 `Φ=0`。一步奖励为 `基础终局奖励+Φ(next)−Φ(now)`。按同一国家的相邻决策累积区间奖励 `R`，记中间真实经过的国家回合数 `ΔT`，使用 `β=0.95^(ΔT/6)`、`δ=R+V(next own)−V(now)`、`A=δ+β·A(next own)`，价值目标 `V_old+A`。另存完整实际回报供诊断。异常截断不判负，整局不进更新。

PPO：`γ=1`，clip 0.2，Adam 3e−4，4 epoch，minibatch 256，熵系数 0.01，价值 MSE 系数 0.5，梯度范数限制 0.5。每批固定采样网络，收完自然终局对局才更新。检查点保存网络、优化器、维度/schema、事件名单、课程、规则构建 SHA-256、训练步数、下个种子以及 Python/Torch 随机状态。恢复时拒绝课程或规则构建不匹配。

## 实测

两个首批运行均为 **CPU、单训练进程、约 4096 个完整决策**，各自训练一个更新；没有启动长期训练。规则构建 SHA-256：`51334428e63c6b7e97bbf988ddc7750f06165524a22d73a69857068d4df0448e`。

| 课程 | 完整对局 | 有效决策 | 截断 | 采集时间 | 采集吞吐 | 全程时间 | 平均终局轮次 | 轴心/同盟胜局 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A | 30 | 4259 | 0 | 221.25 s | 19.25 决策/s | 250.27 s | 8.13 | 1 / 29 |
| B | 28 | 4104 | 0 | 197.52 s | 20.78 决策/s | 222.89 s | 8.36 | 0 / 28 |

A/B 更新的价值初始 MSE 分别为 0.532/0.513，合法策略熵 1.616/1.541，近似 KL 接近 0，clip 比例均为 0。不能把这一批自博弈胜率看成网络强度；该资源课程的随机初始策略和规则本身也可能形成显著阵营偏差。

检查点恢复后，对每个网络用训练之外的固定 3 个种子，在 A、B 各让学习者分别控制轴心/同盟，对手使用同一个冻结的加权合法动作策略。每个交叉组合是 6 局：

| 训练课程 | 评估 A 学习者胜局 | 评估 B 学习者胜局 | 其中学习者控制轴心胜局 |
| --- | ---: | ---: | ---: |
| A | 2/6 | 3/6 | 0/6，0/6 |
| B | 3/6 | 2/6 | 0/6，0/6 |

这只是固定对手和少数种子的管线复验，不能表述为“已学会取舍”或“可用人机”。详细各局赢家、分差、轮次见同名 `*-eval.json`。

资源采样另用 A 课程 279 决策的两局演示运行：其中 55 次来源选择为事件。启用摘要日志后，采集 15.07 秒；Windows 进程采样中 Node 竞技场工作集约 130→212 MB、Python/PyTorch 约 586→748 MB，采样和更新结束时合计约 960 MB 工作集，GPU 内存使用为 0。该内存数字来自小批次离散采样，**不是** 4096 批次的峰值；首批全程未持续监测内存。现有吞吐表也主要包含推理、规则推进和观察编码，不应当作纯环境基准。

## 验证与边界

`node node_modules/typescript/bin/tsc --noEmit` 通过；Vitest 全量 75 文件、795 项通过；Python 数值测试 5 项通过。测试覆盖 58 ID/卡表匹配、平衡资源、A/B 开放边界、正式卡效隔离、跨国绑定效果结构、错误/过期动作、快照恢复、未开放资源的随机弃牌、对手开放信息隔离、自然终局嵌套选择、奖励望远镜相消、`ΔT=0/1/6`、候选 mask、PPO 更新方向及检查点前向一致性。

尚不能把上述测试说成 58 张事件所有地图局面的逐张证明。特别是动态补给、某些事件产生的复杂绑定状态及特定残局尚需更多定向场景测试；观察向量对规则效果按固定槽编码，但没有记忆网络，无法由当前可见信息恢复全部历史。日志的 `summary/full` 级别可以用于定位这些场景。策略评估样本很小，后续训练应继续固定评估种子和对手，并对轴心明显劣势作单独诊断，不能私自调整胜利门槛或叠加临时奖励。

## 复现命令

在项目目录运行：

```powershell
python scripts/ppo_train.py --mode A --updates 1 --batch-decisions 4096 --seed 20260929 --checkpoint outputs/ppo-first-step-A.pt --report outputs/ppo-first-step-A.json --cpu
python scripts/ppo_train.py --mode B --updates 1 --batch-decisions 4096 --seed 20261029 --checkpoint outputs/ppo-first-step-B.pt --report outputs/ppo-first-step-B.json --cpu
python scripts/ppo_train.py --mode A --updates 0 --resume --checkpoint outputs/ppo-first-step-A.pt --eval-seeds 3 --report outputs/ppo-first-step-A-eval.json --cpu
python scripts/ppo_train.py --mode B --updates 0 --resume --checkpoint outputs/ppo-first-step-B.pt --eval-seeds 3 --report outputs/ppo-first-step-B-eval.json --cpu
python scripts/ppo_train.py --mode A --updates 1 --batch-decisions 128 --seed 84 --checkpoint outputs/ppo-record-demo.pt --trace full --log outputs/ppo-record-full.jsonl --cpu
node node_modules/vitest/vitest.mjs run --maxWorkers=2 --testTimeout=15000
python -m unittest discover -s tests -p test_ppo_train.py
```

原始产物在 `outputs/ppo-first-step-*.pt/json/log`；样例操作记录在 `outputs/ppo-record-demo.jsonl`。继续训练时使用相同课程检查点加 `--resume --updates N`；改动规则或编码后必须重新建检查点。
