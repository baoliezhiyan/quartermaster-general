# PPO 第一步独立验收修正复验

日期：2026-09-29。依据用户提供的《PPO第一步独立验收报告-20260929.md》逐项修正。此文替代旧《PPO第一步实现与复验-20260929.md》的**当前实现**描述；旧文及首批 4096 决策结果只留作历史测量。新观察/动作 schema 均为 v2，规则构建 SHA-256 为 `5c33b36a0f6b5ec7b2e79ba8979ad0e1a3d7771632330e1e9c152279d8cf414c`。

## 已修正

1. **效果及结算上下文编码**：巴巴罗萨来源明确标识“预承诺 1–3 目标、最多三次陆战”。效果按顺序保留所有限制地区、目标单位的国家/兵种/地区、已选单位、选择字段、绑定键、实际绑定单位及前序效果结果；目标身份由可见部队映射为稳定语义，不把随机单位 ID 输入网络。未知目标无法转成可见语义时明确报错，效果槽或目标槽超限也报错，不静默截断。实际中途快照测试覆盖巴巴罗萨、百团大战、先开火后谈判，语义改变时向量不同。
2. **目标顺序**：巴巴罗萨的 2/3 目标候选改为有序列表，执行前一次性承诺。三目标时包含 3+6+6=15 个列表；调换底层单位数组顺序不改变合法列表全集。引擎 `EXTRA_TARGET` 多目标顺序同样保留。
3. **副本合并**：`EXTRA_CARD` 与普通来源选择一样，在单张主动出牌选择中合并语义相同的基本牌实例，仍提交一个真实实例 ID。武器援助的实际受援国节点及构造的额外出牌节点均验证；随机费用继续从真实剩余实例抽样。
4. **检查点契约**：严格比较奖励参数、PPO 参数、训练器版本、Python 训练代码 SHA-256、编码字典 SHA-256、A/B 模式、`basics/events` 牌组、schema、规则构建指纹、事件名单及网络维度。缺少版本或篡改参数即拒绝恢复。旧 v1 检查点已实测拒绝；新的 A/B 检查点已实测恢复。
5. **统计**：国家回合数改为每步 `turnsAdvanced` 的实测总和，自然结束与被弃用的截断分别列示；来源选择、真正提交、完成结算与终局资源消耗分别命名和计数，不能再把选择次数写作“事件打出数”。任何批次一旦出现异常截断，当前基线直接停止更新并要求排查。
6. **基础对照**：新 PPO 竞技场增加 `--card-set basics`，与 58 事件课程使用相同观察和动作接口；牌组进入竞技场配置哈希及检查点校验。A/B 仍分别训练。

新编码维度：局势 **14,491**，候选 **10,465**，共享网络 **5,197,826** 参数。增加的维度主要用于完整的地区顺序、目标语义和绑定上下文；明显高于 v0.3 的网络规模预估，后续可在保证语义可区分的前提下压缩。旧网络权重不能直接载入。

## 小规模复验

均为 CPU 单批、自然终局、一次 PPO 更新，`batch-decisions=64` 只是开始新局的目标；完整对局可能超过 64 决策。

| 课程 | 完整对局 | 实际决策 | 实际国家回合 | 异常截断 | 事件选择/提交/结算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A＋58 事件 | 1 | 87 | 24 | 0 | 20 / 20 / 20 |
| B＋58 事件 | 1 | 102 | 30 | 0 | 25 / 25 / 25 |
| A＋四基本牌 | 1 | 224 | 78 | 0 | 0 / 0 / 0 |

新 A/B 检查点各用训练外固定 1 个种子，在 A/B 课程分别以学习者控制轴心、同盟对阵冻结加权合法动作对手，每网 4 局，均自然结束；A 网的学习者赢 2/4，B 网赢 1/4，学习者控制轴心的 4/4 场均未获胜。样本极小，只验证评估及恢复管线，不说明已达到可用强度，更不能据此调整规则。细节及逐局事件选择/提交/结算见 `outputs/ppo-step1-repair-v2-*-eval.json`。

验证：`tsc --noEmit` 通过；Vitest 全量 **75 文件、801 项**通过；Python 数值与中途语义 **8 项**通过。新增测试覆盖三目标排列、实际额外出牌副本合并、B 课程 120 种子的开放频率、首轮与次轮刷新、跨国武器援助不重抽、旧检查点拒绝与新检查点恢复。补丁仍不是 58 张事件在所有棋盘局面的穷尽证明；正式扩大训练前，应继续收集失败种子并补专项场景。

## 主要文件与复现

- 规则适配：`src/training/ppoArena.ts`、`src/core/trainingCourse.ts`、`src/core/specialCards.ts`、`src/core/extraCards.ts`、`src/core/decks.ts`
- 训练：`scripts/ppo_train.py`、`scripts/ppo-arena-server.mjs`
- 测试：`tests/ppo-arena.test.ts`、`tests/test_ppo_train.py`、`tests/test_ppo_semantics.py`
- 新检查点及报告：`outputs/ppo-step1-repair-v2-{A,B,basics}.pt/.json`

```powershell
python scripts/ppo_train.py --mode A --updates 1 --batch-decisions 64 --seed 926531 --checkpoint outputs/ppo-step1-repair-v2-A.pt --report outputs/ppo-step1-repair-v2-A.json --cpu
python scripts/ppo_train.py --mode B --updates 1 --batch-decisions 64 --seed 926532 --checkpoint outputs/ppo-step1-repair-v2-B.pt --report outputs/ppo-step1-repair-v2-B.json --cpu
python scripts/ppo_train.py --mode A --card-set basics --updates 1 --batch-decisions 64 --seed 926533 --checkpoint outputs/ppo-step1-repair-v2-basics.pt --report outputs/ppo-step1-repair-v2-basics.json --cpu
python -m unittest discover -s tests -p test_ppo*.py
node node_modules/vitest/vitest.mjs run --maxWorkers=2 --testTimeout=15000
```

以上训练命令会覆盖同名产物，复验时可换新的输出文件名。继续训练须保持同一规则与 Python 源码版本并使用 `--resume`；修改编码、奖励或优化配置后应重新训练。
