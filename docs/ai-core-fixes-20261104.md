# AI 收尾所需的两处正式缺陷修复（2026-11-04）

基线：3831dec，游戏仍为 v1.8.4。此次用户明确授权最小核心修复，不调整卡牌、玩法或结算优先级，不改文件协议、不放宽回放身份检查。最终验收、构建身份见 local-ai-actions.md。

## 已选行动失效

原 validEffect 在尚未生成 option 时，仅检查整个 boardOptions 是否非空，忽略已经填写的 selection。AIR_INTERCEPT 时已选发起部队被 GM 删除、另一发起部队仍合法，造成 Validate 认为有效，但后续按原 selection 得到空数组，反复赋值 undefined 并重试。对已选守军、地区或已回答拦截方案失效也采用同一判断。

现在仅在未生成 option 时，要求候选同时满足已有 regionId、defenderId、attackerId、airIntercept；已有 option 仍按原方案 ID 校验。已有选择失效则走原 EFFECT_INVALID 分支并推进游标，不替换部队或目标，不重新扣费、不重复已完成响应、不增加循环上限。

已宣告并进入 Apply 的战斗仍沿用原撤退处理：守军撤离后，若同一发起部队仍可攻击该空地区，可按原规则继续；此修复没有删除该路径。用户既有的撤退后触发、时点优先级不变。

复现边界：已证实的是 GM 场景编辑改变当前 AIR_INTERCEPT 的部队。正常 AIR_DEFENSE/AIR_INTERCEPT 处理只写入选择和通知，随后同步执行，不插入另一个可移动该发起部队的响应窗口；本次没有找到不用场景编辑即可自然到达这一具体循环的证据，不能声称普通对局已经复现。Apply 阶段普通响应导致方案失效的既有校验继续保留。

验证：selected-action-refresh 覆盖有/无替代发起部队、守军移除/移动、地区失效、拦截所需空军方案失效、费用仅支付一次、原牌只弃一次及正常拦截。local-ai-actions 覆盖合并请求暂停后 GM 删除部队，刷新和旧请求重试不执行剩余参数。独立超时探针还断言原结算结束、invalid 事件、守军保留；不再把超时作为通过。

## 恢复校验

saveFormat 的 recovery 重演及 commands 重演原以 JSON.stringify 比较；初始载入的只读回放节点检查也有同类比较。改用已有 network/jsonPatch.diffValue 的零差分判断，仍先运行全部结构校验。

JSON 对象键顺序不参与相等判断；数组元素位置和长度严格保留。缺失字段与显式 undefined 按 JSON 序列化语义等价；缺失与 null/false/0/空数组等具体值不等价。必需字段缺失首先被 validateState 拒绝。没有对状态做 ruleState 裁剪，也没有忽略分数、牌库顺序、单位、日志或私有牌区。

recovery-order 覆盖正式 restoreHostSession 接口的键序、真实值/位置、牌库顺序和缺失字段；verify-ai-actions 使用构造多轮局，实际持久化、退出服务、重启后调用 Room 的 restore（普通“恢复主机对局”入口），不以 importSave 替代。恢复后核对牌区、单位、分数、随机状态及阶段，查询旧 AI 回执，重试原请求不执行，再读取观察并完成新行动。

## 训练与兼容

共享引擎的已选方案失效行为改变，训练若使用此路径必须同步并重新冻结规则指纹；独立优化内核需自行差分验收。未改 PPO、课程、奖励或观察/动作编码，未运行训练。主机恢复修复不改训练规则，但使用正式持久化的工具应同步。

存档/回放 schema 和游戏版本不变。旧 JSON 状态在原校验、重演和结构均一致时仍可读；需要重新执行旧命令的文件若依赖旧错误行为可能不一致。新规则指纹正常生成，严格身份校验仍会拒绝旧指纹动作回放及带旧身份记录的主机档案；未提供跨指纹迁移器，不复制旧身份伪装兼容。纯快照训练回放按既有审查过的身份适配范围处理，不增加泛化豁免。
