# v1.8.3 客户端、规则与回放修订

日期：2026-10-26。基于客户端 124437d（v1.8.2）；训练分支仅选择性移植观看适配，不合并训练执行、奖励、PPO 或禁用资源重整的逻辑。

## 正式规则与展示

- 所有模式：可见弃牌采用 `publicDiscardHistory`（按国家、卡牌实例 ID 去重），与实际弃牌区分开。公开弃置的牌被秘密回收到手牌/牌库后，历史仍保留；再次公开弃置同一实例不增加重复项。本人实际弃牌堆仍只含当前在堆内的牌。历史不推断秘密回收去向。旧状态只能补入其仍保存的公开弃牌，不能补造已丢失的历史。
- 西班牙蓝色师、代号 Magic 的平衡效果：弃掉刚公开的响应时进入可见历史；随机弃未公开响应不公开该牌，卡主仍收到私有通知。
- 补给：原清除列表会同时包含陆海军及附属空军，导致免费调度后仍执行过期的空军移除。现在先处理陆海军，再处理空军；执行补给移除空军前检查当前补给，已经调到有补给位置的空军不再被移除。无合法目的地仍回储备。战斗等非补给移除不因此免除。
- 平衡响应 `special_249`（突袭珍珠港）：结束美国中立属于强制代价，不是可选效果。美国已经非中立时不重复处理。

## 正式记录与 GM

- `formatVersion=3/action_replay` 保持；正式导入仍要求精确游戏版本、引擎及 schema 身份。1.8.2 文件不伪装为 1.8.3。
- 记录所有 TRIGGER 跳过，包括 `guided` 参数；不再假定空选择没有状态语义。旧逻辑的漏参导致实际状态 `resolution.guided=true`、自动重演为 false，触发摘要不一致。没有删除该字段或绕过摘要校验。
- 新增独立 `editor_change` 根动作，输入为 `{type:'EDITOR_STATE',beforeHash,state}`。`state` 使用既有 Snapshot 编解码，保留结算恢复信息；允许 GM 控制动作携带完整后状态是普通动作禁带快照规则的唯一新增例外。
- 编辑前若有未结束动作，封存到编辑前状态；完整保留此前历史。重演验证前摘要、后摘要、gameId、状态结构，直接恢复编辑后状态，不重复执行编辑时产生的随机/副作用。其余动作仍引擎重演。
- 编辑快照不能作为子响应/选择注入；原有服务器 GM 权限不变。回放始终只读；编辑条目支持前后查看、继续记录、回退/导入。

入口：GM → 存档、读档与备份 → 导入回放。仍使用地图、国家信息、卡牌索引、手牌和牌区、右侧回放列表，无独立审计界面。真实手牌隐藏资源池入口。

## 训练影响与兼容边界

共享引擎行为改变：补给空军移除、珍珠港强制代价；公开弃牌历史与记录结构也有新增。训练执行端需要另行同步并冻结新指纹，本次未修改任何在途训练产物。新增训练观看能力不代表任意未来训练 schema 自动兼容。资源池继续用原 v3 场面适配器；旧指纹资源池记录不自动放行。

客户端新增/移植：realHandTrainingReplay、openReplay、ReplayRecord、LocalTools、MapPanels、TableHand，以及必要的只读状态类型。没有复制旧 build-identity.json；构建正常生成新身份。
