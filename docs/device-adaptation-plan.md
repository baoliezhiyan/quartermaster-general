# 多设备横屏适配开发方案

日期：2026-10-05。基线：客户端 v1.7.7，源码提交 `2f07a85`。
状态：方案已用于 v1.8.0 首轮实现；实施范围、自动化结果及实机限制见 [v1.8.0 验收说明](client-v1.8.0.md)。

## 1. 已确定范围

- 同一个网址支持桌面电脑、平板和手机；共用正式规则、联机、保存及回放实现。
- 手机只支持横屏，不开发竖屏游戏布局。平板也以横屏为本期支持范围。
- 自动按可用窗口尺寸和输入方式适配，不要求玩家先选手机或电脑入口。
- 保留桌面现有操作；手机适当缩小卡片和留白，通过滚动、折叠保留可读性。
- 下述尺寸为首轮实现参数，可以通过验收调整；不是已经验证的设备兼容承诺。

## 2. 当前实现与需补齐部分

当前页面已有 viewport 配置。`src/ui/map/camera.ts` 与 `GameMap.tsx` 提供地图相机、缩放按钮和 Pointer Events 拖动；地图使用 `touch-action: none`，当前并没有完整的双指缩放支持。地区详情包含右键交互，需要触屏替代入口。

`src/ui/map/map.css` 已有部分媒体查询，但手牌区、交互区和侧栏仍需统一适配，尤其是横屏高度较低时。`TableHand.tsx` 的手牌可排序，出牌通过明确按钮完成；移动端横向浏览不能触发排序。`DraggableWindow.tsx` 使用指针捕获，需要避免与弹窗内容滚动争用手势。

实施前还需盘点全部弹窗和牌区入口，不能只修主地图及普通手牌。

## 3. 设备判断与布局档位

使用 CSS 媒体查询为主，确实涉及行为差异时统一读取响应式状态；不在各组件分别猜测设备。布局尺寸和输入方式独立判断：触摸电脑仍需触摸操作，大屏平板也不能依赖右键和悬停。

| 档位 | 首轮建议条件（CSS 像素） | 默认布局 |
| --- | --- | --- |
| 桌面宽屏 | 宽度 ≥ 1200 且高度 ≥ 650 | 保留现有地图、右侧记录和底部栏 |
| 平板／紧凑窗口 | 其余空间较充足的横屏窗口 | 紧凑工具栏；记录可收起；卡区适应可用宽度 |
| 手机／低高度窗口 | 宽度 < 960 或高度 < 500 | 默认收起记录；底部紧凑操作栏；卡片横向浏览 |

- 条件优先级：低高度布局优先于宽度较大的布局。不能把宽而矮的手机误当桌面。
- 以布局视口决定档位，软键盘出现时只调整可见区域，不因键盘高度导致反复切换布局或方向提示。
- 同一设置入口提供“自动／桌面布局／紧凑布局”，仅本机保存；输入方式检测独立生效。默认自动，无需进入前选择。
- 按用户后续裁定，不进行方向检查，不显示旋转提示或遮挡层；浏览器即使报告竖屏也直接进入现有布局，不要求方向 API 或全屏权限。
- 尺寸适配只影响本机显示，不暂停房间、不替玩家响应，不向主机发送游戏指令。任何方向均不阻挡入口和操作。
- 手机直接通过浏览器加入房主网址；本期不把 Windows 的 cmd 本地资源客户端移植到手机，也不新增手机安装包或离线承诺。

## 4. 布局与交互要求

### 4.1 地图与顶部栏

- 地图使用顶部栏和底部栏之外的剩余空间，地图几何、地区归属和规则邻接均不改变。
- 顶部保留地图入口、比分和必要菜单；搜索、边界显示、标准视图、全卡图鉴等收进可展开工具区，避免挤占整行。
- 单指拖动平移，双指以手指中心为参照缩放；沿用相机边界约束。
- 拖动或双指操作结束后不触发地区选择；处理 pointercancel、失去捕获、从双指变单指等情况。
- 点地区选择，提供明确“地区详情”入口；不要求用户长按或模拟右键。
- 小兵模扩大透明点击范围，但不得让相邻兵模互相遮挡；多个候选难以区分时提供带国家、兵种的候选列表。
- 视角锁定时禁止平移缩放，但保持合法目标选择和详情查看。
- 地图手势仅在地图区域生效，不能吞掉卡片、侧栏和弹窗滚动。

### 4.2 右侧记录、聊天与国家信息

- 紧凑布局默认收起，点击入口以覆盖式侧栏展开，不反复压缩地图。
- 六国入口、记录／聊天切换和未读气泡保留。侧栏内部滚动，不推动整个页面。
- 记录展开后宽度以可读文字为准并限制在屏幕内，必须有明显关闭按钮。
- 普通侧栏与手牌可以按互斥方式展开以节省空间；关闭面板不清除已选择的牌、目标或滚动位置。
- 需要自己响应、多控国家切换、提交失败和连接状态提示放在常驻区域，不能因为侧栏关闭而不可见。
- 点击通知中的切换入口遵循现有确认语义，切换后定位到实际需要操作的国家。

### 4.3 底部操作与四类牌区

- 当前轮次、当前国家、阶段及主要行动始终可找到。低频的手牌／牌库／弃牌／持续生效等入口允许横向滚动或进入“更多”。
- 普通手牌采用单排横向滑动，露出下一张卡片边缘提示可继续滑动；不把七张牌硬塞进一屏。
- 小屏卡片以卡名、类型和选择状态为主，点击详情可读完整效果；不能把关键文字永久裁掉。
- 普通牌库、弃牌、序章牌区、持续生效牌、兵模储备以及回放资源池均需可访问；顺序和信息权限与当前模式一致。
- 初始选牌、费用多选和手牌排序分别处理。初始十二选七显示已选数量；费用多选显示数量和要求；滑动不改变选中状态。
- 触屏默认关闭直接拖动手牌排序。需要排序时进入独立“整理手牌”模式，明确退出，不把正常浏览解释为排序。
- 选牌与提交分开：滑动、查看详情和关闭面板不出牌，明确点击现有提交按钮才发送指令。
- 手牌排序和列表位置继续使用稳定卡牌实例 ID，不能因为窗口改变而重新排序。

### 4.4 询问、选牌及详情弹窗

- 所有弹窗统一使用可用宽高上限；标题、关闭／暂收入口和底部确认操作可见，内容区单独滚动。
- 对低高度横屏，压缩装饰与留白，保留问题、已选数量、费用和按钮，不通过缩小全部文字解决溢出。
- 候选牌按当前规则确定的 ID 顺序显示，使用横向列表或少量列的滚动布局；排序选择类弹窗仍保留明确的顺序数字。
- 当前需要查看地图时允许“暂收选择面板”，保留待处理问题、已选项目和重新展开入口。暂收不等于跳过，不让玩家越过未完成决策继续操作。
- 地图选目标时收起遮挡目标的卡片面板，显示紧凑的问题提示及确认区。
- 移动端不依赖拖动弹窗避让地图；桌面继续保留拖动，拖动只从标题区域开始，内容区负责滚动。
- 回放中的同类窗口是历史展示，不能出现向房间提交响应的路径。

### 4.5 图鉴、GM、入口与软键盘

- 全卡图鉴按可用宽度减少列数；国家按钮和序章开关可滚动，保持 ID 排列、基础牌数量和卡牌详情。
- 身份入口、创建用户、座位选择、切换国家也纳入适配，不能只有进游戏后才可用。
- GM编辑器、存档导入导出和回放按钮使用可滚动内容区；保留现有权限与只读限制。手机沿用浏览器文件选择和下载能力，需要单独实机验收。
- 聊天输入时，输入框和发送按钮保持在可见区域；键盘关闭后恢复布局，不重置地图与聊天位置。
- 处理浏览器地址栏展开收起、动态视口和屏幕安全边距；全屏可选，不是游玩的前置条件。

## 5. 视觉与状态管理原则

- 不对整个网页使用统一 transform 缩放。卡片尺寸、间距、字体和按钮分别设置响应式变量。
- 首轮以正文约 14–16 CSS px、常用触摸目标约 44 CSS px 为调整起点；低高度下优先减少同屏内容，不无限缩小字体。
- 支持保留浏览器缩放，不通过禁止用户缩放解决手势冲突。
- 页面容器固定可用空间，各面板明确滚动轴；避免页面、弹窗、卡片三层同时争夺滚动。
- 尽量复用同一组件树及数据源，不同时渲染隐藏的桌面版和手机版，不额外生成第二份国家视角数据。
- 旋转、侧栏开关、尺寸变化不重连房间、不重复提交操作、不触发规则重算或额外随机调用。
- 展示偏好只保存在本机界面状态，不进入游戏存档、网络权威状态或回放协议。
- 断线或权威状态更新导致原选择失效时遵循现有合法性检查并提示，不能为了保留界面状态而提交过期选择。

## 6. 实施顺序与交付边界

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 | 清点全部面板、统一布局变量与档位、无方向限制的入口、侧栏及工具栏 | 手机横屏可以进入房间、切换国家，地图与关键按钮无遮挡；桌面无明显回退 |
| 2 | 地图触摸、手牌滑动、排序隔离、卡片详情 | 可稳定区分点选／拖动／缩放；不误选目标、不误出牌 |
| 3 | 所有询问与多选窗口、响应通知、GM及回放、图鉴 | 正式流程与辅助功能均可操作；暂收窗口不丢选择、不越过响应 |
| 4 | 固定场景验证、设备检查、性能比较、发布 | 下述验收有结果及限制记录，版本、指纹、发布说明一致 |

本方案首轮实现使用客户端独立工作目录和聚焦提交，发布版本为 v1.8.0，不同时修改平衡规则。未完成的实机验收见版本说明。

## 7. 验收清单

### 7.1 屏幕与浏览器矩阵

首轮自动化视口：手机横屏 667×375、844×390、915×412；平板横屏 1024×768、1180×820；桌面 1366×768、1920×1080。另测浏览器工具栏和软键盘造成可见高度减少，以及缩放后字体增大。尺寸均指 CSS 像素，不是设备物理分辨率。

使用后台浏览器或无头环境，不抢占用户桌面。自动化中模拟触摸不等于真实设备验收；最终至少覆盖 Android Chrome 与 iOS Safari 的真实触摸、键盘、横竖屏切换和下载。没有设备时明确列为未验证，不宣称全设备通过。微信内置浏览器单独列为待验证，不能用 Chrome 结果替代。

### 7.2 必测流程

- 身份创建／返回、加入座位、多控切换、观察者与GM权限。
- 十二选七、普通出牌、费用多选、序章出牌与弃牌、资源重整。
- 陆海军建设、陆海战、空军部署／调度、地图多目标选择（包含战区移动）。
- 连锁响应、对方等待、自方跳过、多控通知、提交中与断线重连。
- 所有牌区、图鉴、卡牌索引详情、聊天未读与输入、国家信息。
- 存档导入导出及部分导出、进入／退出回放、回放逐步定位及资源池展示。
- 手势取消、滑动起点在卡片上、双指后抬起一指、旋转时正有费用选择、键盘弹出时正收到响应。
- 桌面鼠标、右键、滚轮与现有拖动交互回归；触屏设备上的外接鼠标不被禁用。

### 7.3 正确性与性能

- 固定种子和相同操作轨迹，对比适配前后权威状态及回放动作；UI开关和手势不新增游戏命令或随机调用。
- 保持各国家暗牌、选择菜单及GM权限的原有过滤，面板折叠不改变数据访问权限。
- 小屏所有确认／取消／跳过按钮可触及，无必须拖出屏幕才能操作的弹窗；卡名、费用和当前问题可读。
- 固定局面测地图拖动、手牌滚动、弹窗打开和响应提示的耗时、帧表现与重渲染次数，记录设备／浏览器；不把主机网络等待误算为移动端渲染耗时。
- 只在出现实际热点时增加列表虚拟化等优化，需保留滚动位置、焦点、ID顺序及选择；不借适配重写规则引擎。
- 正常联机与回放验收分别记录；不能用本地静态页面验证替代多人响应验证。

## 8. 规则、训练和协议影响

本方案只涉及客户端展示和输入，预期不修改卡表、地区几何、邻接、补给、费用、触发顺序或随机过程；不修改训练课程和观察／动作 schema，不新增回放字段。实施若发现必须跨界修改，需要单列原因、兼容性及回归验证，不在UI改动中静默处理。

界面源码更新可能改变构建指纹；发布时核对游戏界面、网页标题、包名和指纹。规则指纹应按实际构建机制复核，不为兼容旧文件手工伪造。未确定发布版本前不承诺旧存档／回放跨版本导入。

### 2026-10-06 全屏兼容修正（v1.8.0）

移除“切换横竖屏”按钮及网页旋转，始终使用浏览器实际视口。全屏按钮优先请求原生全屏；接口缺失、禁用或请求被拒绝时，自动在当前页面展开游戏，可点“退出展开”恢复。页面内展开不代表隐藏了浏览器地址栏，也不替代系统旋转。iPhone 如需横屏，请解除系统竖排方向锁定并横持手机；网页不能强制弹出系统横屏提示。不再因手动旋转禁用全屏按钮。

仅改变显示层，不改变规则、随机数、网络或回放协议。后台浏览器检查缺失和拒绝全屏接口的降级、恢复及视口变化；真实 iPhone / Safari 仍需实机验收。
