战场军需官 1.8.4-ai增强版
游戏版本：1.8.4；AI接口：以 version/ai-build.json 为准。
包含已验收的接口收尾及两处核心缺陷修复；确切源码与构建身份见 version/ai-build.json。
本包自带 runtime/node.exe，无需安装 Node、pnpm 或开发依赖。

一、启动
要和当前聊天中的助手对打：双击“启动本机AI接口.cmd”。
浏览器普通客户端：http://127.0.0.1:4183/
AI接口仅监听本机：http://127.0.0.1:4185/
不用AI：双击“启动本地版游戏.cmd”，AI端口默认关闭。
两个启动入口共用同一个房间/data目录，一次只运行一个。
重复启动会提示数据目录或端口已被占用；不要删除正在使用的锁。
保持服务窗口开启。关闭或 Ctrl+C 停止。

二、创建AI身份（不会自动占座或新建游戏）
在普通客户端新建一个专供AI的用户。进入想让AI控制的国家玩家座位，
绑定该国，再绑定同阵营另外两个国家。之后复制这个用户的个人返回链接。
把 local-ai-private/session.example.json 复制为同目录的 session.json，
仅将 token 字段填为该用户返回链接 #identity= 后的身份值。
url 默认 http://127.0.0.1:4185，不需要更改。
凭据保留在本机文件里，不要发到聊天或上传仓库。
人类用自己的另一身份入座。由人类GM选择规则开关并新建/恢复游戏。
告诉助手包的完整解压路径，安排试打。
助手 connect 后接管AI身份；不要再用网页登录同一个AI身份，否则网页会接管连接。
本包提供工具接入，不自带自动决策模型；双击启动本身不会让AI自动出牌。

三、当前聊天助手从解压目录执行
.\runtime\node.exe .\scripts\local-ai-cli.mjs connect
.\runtime\node.exe .\scripts\local-ai-cli.mjs status
.\runtime\node.exe .\scripts\local-ai-cli.mjs observe
.\runtime\node.exe .\scripts\local-ai-cli.mjs reference
.\runtime\node.exe .\scripts\local-ai-cli.mjs wait-decision --wait-id next-001
.\runtime\node.exe .\scripts\local-ai-cli.mjs submit --request-file .\local-ai-private\request.json
合并一个行动并等待下一项己方决策：
.\runtime\node.exe .\scripts\local-ai-cli.mjs submit-action --request-file .\local-ai-private\action.json --wait
查询已执行回执：.\runtime\node.exe .\scripts\local-ai-cli.mjs result --request-id 原请求编号
取消等待：.\runtime\node.exe .\scripts\local-ai-cli.mjs cancel-wait --wait-id next-001
需要全量同步：.\runtime\node.exe .\scripts\local-ai-cli.mjs observe --full
也可用 AI命令.cmd 加同样参数。跨目录请用绝对路径并对空格加引号。

submit 的 UTF-8 JSON 文件格式：
{"requestId":"唯一编号","gameId":"观察中的值","epoch":"观察中的值","revision":123,"offerId":"观察中的值","selections":{"ids":["合法选项ID"]}}
实际 selections 键名和数量看 offer.selections；起手一般是 cardIds，结算选择是 ids。
不要发送任意命令，也不要根据想象猜测ID。过期后重新 observe。
网络异常重试必须沿用同一文件及 requestId，不能另起编号重复动作。
机器输出JSON；非0退出码表示错误，具体看 error.code。

合并请求沿用上述身份与版本字段，增加 intent，例如：
{"requestId":"build-001","gameId":"观察中的值","epoch":"观察中的值","revision":123,"offerId":"当前建设陆军的offer.id","intent":{"regionId":"eastern_europe"}}
攻击可指定 regionId、defenderId、attackerId；调度可指定 cardId、airId、regionId。
状态/响应可指定 feeCardIds 和明确目标；有兵模回收时可指定 recycleId。
只合并本行动，不连带发动闪电战等后续触发。对方响应、新信息、缺失参数或失效会停止，
回执写明已完成步骤和剩余内容；不自动恢复剩余操作，不承诺原子撤回。
wait-decision 在内部续订，只有己方新决定或终止事件才返回；旧 wait 仍是有界等待。
当前聊天工具可能需要通过进程 session_id 续等，不能唤醒已结束的聊天。

四、信息与缓存
观察输出自己的绑定国家手牌、无序牌库组成、暗置牌、当前提示、公开场面和数量。
紧张度字段 tension：数字0是确实为0，null是不适用。未公开敌牌和未知牌序不输出。
弃牌总张数 discardCount 与 visibleDiscard 可见历史不同；历史中的牌可能已被收回。
mapFacts 给出正式查询的动态相邻、补给来源、大本营、部队补给及八国兵模储备。
reference 给出静态地图、基础连接、海峡、印刷兵模等资料。
缓存按规则指纹、资料版本、接口版本和摘要校验；不能把旧资料套在新构建上。
缓存位于 session.json.reference.json；当前观察缓存位于 session.json.observation.json。
紧凑结果中的 changes 含新增公开记录、部队/分数及己方牌区变化；
mode=delta 时须接在匹配 fromHash 的基线上，mode=snapshot 时提供完整必要动态观察。
新的 .delivered.json 是最后输出的观察基线；可用 scripts/local-ai-compact.mjs 的
applyObservationChange 还原。基线不匹配须 observe --full，不能将决策摘要当完整场面。
日志位于 local-ai-private/audit/interface.jsonl 与 bridge.jsonl，合并回执位于 requests/。
这些文件可以含己方秘密牌面，请按私人对局资料保管；令牌不写入日志。

五、暂停和恢复
助手暂停时不提交操作，游戏按正式规则等待；可重新 observe 继续。
disconnect 断开AI连接但保留绑定，connect 后再 observe 可以恢复控制。
服务重启遵守普通客户端流程：游戏不会自动读入，GM先点恢复上次对局，再连接AI。
旧 epoch 的请求会失效，不能盲目重放。
游戏存档和回放仍使用GM原入口；没有专用AI回放客户端。
本轮核心修复产生新规则指纹。同版本且同规则指纹的记录按原校验导入；
旧指纹动作回放及带旧身份记录的主机档案不会自动兼容，未提供跨指纹迁移器。
普通JSON状态仍须满足原结构与重演校验；v1.8.2/1.8.3等异版本记录仍会拒绝。
构建指纹正常生成，没有伪装旧身份或放宽校验。

六、限制
没有内置Qwen、没有模型权重，不调用付费API，不训练。
尚未人工打完完整长局，也未逐张验收所有卡牌组合。
不支持的节点明确 unsupported，遇到拒绝需停止检查，不能自动跳过。
交付包不含真实用户身份、存档、观察日志或构造测试对局。
