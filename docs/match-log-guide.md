# v1.7.4 统一存档与回放

在 GM 的“存档、读档与备份”中统一操作，原“回放查看”入口已合并。导出完整存档会下载截至当前局面的 `.qmreplay.jsonl` 历史文件；导入完整存档会校验历史、恢复末尾局面并替换当前对局，同时重建每轮德国行动前的大存档与六国最近行动前的小存档。旧 JSON 存档仍能导入；没有匹配历史时从快照开始。

“进入回放模式 / 退出回放模式”是同一个按钮，查看当前记录的独立只读副本，右侧记录栏切为回放记录。原地图、兵模、六国与底部牌区继续使用。导出部分存档先选序章/正式第几轮，再选某国行动前，下载截至该点的完整历史前缀，包含重新生成的 end 与校验哈希。

大小存档共用记录格式。全量检查点在正式开局与轮末；检查点后的动作由同版本回放引擎恢复。内部槽位缓存局面以加快读取，并引用当时的历史前缀；加载旧槽位不会破坏其他槽位保存的路线。例如保存到 E 后读 C、走 X，再读 E，可以恢复原 E 的历史。导出的文件只含当前路线，不含已放弃分支或其他槽位。

取消存档导入的 64 MB 限制及标准回放的 96 MB 限制。联机中仅在线 GM、通过来源/身份校验的存档上传放开请求体大小，普通接口保留限制。文件仍需通过格式、版本、结构与哈希校验，实际可处理规模受设备内存和隧道服务自身限制影响。

训练 resource_pool 文件通过同一导入入口进入只读回放，不能恢复为正式可操作游戏。

导入后继续使用原来的地图、兵模、六国详情和底部手牌/牌库栏。右侧切为回放记录；点动作默认看选择前，点击“结算后”看完成状态。“本动作的选择与子效果”可展开定位费用、目标和自动子效果；这些细节在全知视角展示。提供前后移动、按轮定位、自动播放/暂停。全知视角内可切换查看国家；国家/公共视角遮盖其他国家隐私，其他国家动作标题采取保守隐藏。历史询问只读，不需要回答。

“资源池”按钮仅在回放中出现，在序章牌库右侧，复用牌库卡牌展示。标准记录的 `ruleState.resourcePool` 为六国空数组。训练记录另用 `quartermaster-training-scene/1.0.0` 适配器，参见 [训练端输出规范](training-replay-output-v1.md)。其四个牌区按文件显式操作展示，不由出牌自动迁移；不能只改 mode 或版本号绕过适配检查。

退出回放回到在线对局。回放控制器不发送游戏命令、不修改主机存档。文件本身包含完整秘密信息；国家视角遮盖不是文件加密或保密，请勿在仍进行的对局中把全量文件当作公开战报。

主机持续记录在程序目录的“对局记录”，不依赖启动脚本工作目录。运行中的原始 JSONL 尚未封口，应通过游戏内导出获得可直接导入的副本。普通记录追加，pending 更新/回退以原子替换修订。旧文件与外部快照文件分别保留；GM 编辑开启新的 snapshot 记录，不伪造此前历史。旧异步操作由主机提交队列和 revision 校验隔离。

格式为 `quartermaster-match-log / formatVersion=3 / action_replay`。必须匹配当前游戏版本（本版 1.7.4）、引擎/数据指纹和 `quartermaster-standard@2.0.0` 适配器。旧版全量日志不能直接导入；跨版本游戏回放也不自动转换。

## 给开发者的接口

发布包“回放接口”含规范、类型和适配说明。服务模块导出 `parseReplay(text)`（协议/摘要校验）、`validateRecords(records, requireEnd)`、`ReplayPlayer`（重演）和 `seal(records)`。

```sh
runtime/node.exe scripts/validate-match-log.mjs 回放样例/client-standard.jsonl --replay
```

省略 `--replay` 仅验证文件结构和完整性，不宣称规则重演已通过。“回放样例”是固定种子实际客户端命令生成的测试对局，不是玩家存档。
