# 战场军需官：对局记录与回放交换规范

版本：v1.1　日期：2026-09-30

本文及配套 v1.1 字段契约完整替代 v1.0。文档版本为 v1.1；由于必需字段及回退语义改变，文件协议升级为 formatVersion=2。状态/决策/事件结构仍各为 schemaVersion=1。旧规范仅作历史参考，不与本版叠加执行。

交付对象：客户端/回放开发者、训练竞技场开发者。本文独立定义新格式；现有客户端回放和AI训练日志只作迁移参考，不作为正确性标准。本次交付为规范，不表示客户端或训练端已经实现。

配套文件《对局记录与回放字段契约-v1.1.ts》是同一规范的字段名、类型和枚举约定，应一起交给双方开发者；它不是游戏实现，也不是完整运行时校验器。本文规定字段语义及跨字段校验，契约固定序列化结构；双方不能独立改名。不影响兼容的扩展放在命名空间中；改变必需结构或语义须升级协议。

## 1 目标与适用边界

记录应完整回答：当时是什么局面、轮到谁决定、为何需要决定、有哪些合法选择、最终选了什么、随机结果是什么、依次发生了哪些结算、局面如何变化。

同一套文件支持：

1. 正常牌库对局：手牌、牌库、弃牌、暗置、状态，以及可选序章/中立规则。
2. AI有限资源池对局：资源池、开放集合、已消耗资源及弃牌；不伪造手牌或摸牌库。
3. 人类、AI或混合控制。控制者类型与资源模式是两个独立字段，不能假设AI永远使用资源池。

首版实现**事实回放**：直接展示文件中的状态与过程，不依赖当前规则引擎重新执行命令。匹配旧引擎的重新模拟属于附加的“规则复算验证”，不是基本回放的前提。

完整记录保证还原规则事实和所有实际选择，不保证知道人类心中理由或AI未输出的思考过程。模型logit、概率、价值和奖励可作附加诊断，不等同于对局事实。

## 2 三项强制原则

### 2.1 文本日志不是事实来源

“德国打出了【阿登战役】”不足以重放对局。中文描述只是显示层，必须同时保存卡牌实例、来源国家、选择、目标、事件因果和完整状态。禁止解析中文反推规则。

### 2.2 种子和命令都不能单独承担完整回放

只存seed无法抵抗随机调用次数、代码或规则变化；只存command无法保证新版引擎仍得到相同结果。必须保存初始实际状态、每个记录节点的实际状态、每次选择与实际随机结果。

### 2.3 首版优先完整，之后再压缩

每个frame保存完整规范化状态，不使用仅局部差异的patch作为首版必需能力。压缩可放在文件外层；不得为省空间漏掉自动结算、费用或中途选择。以后若引入增量格式，应升级版本并提供无损转换。

## 3 文件封装与记录顺序

新格式标识：`quartermaster-match-log`；`formatVersion: 2`。不要复用现有`quartermaster-replay/version:1`标识，两者结构和承诺不同。

规范载体是UTF-8、无BOM、LF换行的JSONL，每行一个JSON对象，最后一行也有LF。一份文件只记录一局/一个记录会话。建议扩展名`.qmreplay.jsonl`；下载时必须已形成可用文件，不能交付0字节占位文件。

最外层记录顺序：

| 顺序 | recordType | 要求 |
| --- | --- | --- |
| seq=0 | header | 模式、版本、规则、地图、卡表与生产者身份 |
| seq=1 | start | 本次记录的起点状态 |
| seq=2…N-1 | frame | 按真实发生顺序追加的选择/随机/自动/控制节点，每条都有完整后状态 |
| seq=N | end | 记录结束原因、最后状态引用、胜负和文件完整性信息 |

seq在当前保留文件中从0连续递增，是该文件内排序唯一依据。不得用时间戳排序，不得用游戏revision代替seq。正常运行追加；回退按第9节截断，之后可以复用被删除后缀的seq。跨导出或诊断引用必须使用(recordingId, recordingRevision, seq/decisionId)，不能只用seq。

正常frame的beforeStateSeq指向前一条start/frame，afterState即该frame.state。start和所有frame.state都带相同的stateSchemaVersion。

多个训练对局不得直接拼接成一个同格式文件。可以另做外层批次目录/容器，但每局须能独立提取且保有自己的header/start/end。

## 4 文件头：先判模式，再决定界面

header必需字段：

| 字段 | 约定 |
| --- | --- |
| format / formatVersion / recordType / seq | 固定标识与版本、header、0 |
| recordingId | 本次记录会话唯一ID；同一主机记录多次导出保留；另开记录生成新ID |
| recordingRevision / historyPolicy | 非负整数，初始0，每次截断加1；historyPolicy固定为`truncate_on_undo` |
| gameVersion | 本局所基于的客户端游戏版本，正式对局导入须与当前客户端完全相同；不能使用训练器版本代替 |
| compatibility | 正式模式为`exact_game_version`，资源池为`declared_schema`；requiredFeatures列出播放器必须识别的展示能力ID |
| matchId | 逻辑对局ID，不能拿训练seed代替唯一ID |
| createdAt | ISO时间，仅供展示，不决定顺序 |
| producer | name、version、buildFingerprint；区分客户端/竞技场等生产者 |
| mode | `standard`或`resource_pool` |
| capture | `full_fidelity`；不完整旧日志不得谎报此值 |
| stateSchemaVersion / decisionSchemaVersion / eventSchemaVersion | 本规范首版各取1 |
| origin | `creation`或`snapshot`；后者须写起点轮次/阶段和来源说明 |
| rules | 规则包ID/版本/指纹、平衡补丁、序章/中立开关、回合顺序、计分/胜负配置 |
| resourceConfig | 模式专属配置，见下文 |
| participants | 匿名稳定controllerId、human/ai/system、显示名；不存连接令牌、登录凭据 |
| controllers | 初始六国控制映射；法国/中国为部队国家，不伪造第七/第八个玩家回合 |
| catalog | 本局卡牌定义快照：唯一catalogEntryId、definitionId、名字、实际文本、类型、牌面国家、资源所属国、实例数量及课程覆盖；各国基本牌可能共用definitionId，不能因此覆盖彼此的牌面 |
| map | 本局地图版本及地区/邻接/海峡/基础补给/大本营数据快照；美术资源另用asset引用 |
| seed / rngDefinitions | seed可null；每个随机流算法ID/版本及用途；结果仍必须记录 |
| capabilities | 如privateViews=true、nativeVerification=false、aiDiagnostics=false；不支持的能力不得标true |

`rules.version`不能只有源码中的通用“1.4.0”，必须能区分平衡补丁、课程覆盖、卡表和引擎实现。gameVersion、producer.version、rules.version/fingerprint及formatVersion分别表示游戏版本、生产程序版本、规则版本和文件协议，不得混用。按用户要求，正式对局即使仅游戏UI版本不同也拒绝导入；资源池记录不做游戏版本相等限制，而是校验协议、状态schema及必需展示能力。规则复算/续玩还必须匹配原生引擎，事实回放不运行该引擎。

### 4.1 standard配置

resourceConfig包含牌库/起手/保留数量/手牌上限等实际规则及各国构成。正常模式必须有常规卡区，按开关包含序章卡区。对局里有AI玩家仍然是standard。

### 4.2 resource_pool配置

resourceConfig必须明确：课程ID/版本、A/B或其他开放策略、基本牌数量、非基本白名单、开放概率和抽样公式、刷新周期、随机费用来源、缺额处理、各卡覆盖。

当前第一阶段以《战场军需官PPO第一步实施方案-v0.3.md》为冻结依据，必须完整声明以下配置。它们是本阶段生产者的导出要求，客户端不能把这些常量硬编码为所有未来训练局的规则。

- cardSet=`basics`表示四类基本牌对照；`events`表示四类基本牌加58张白名单事件；未来课程可用`custom`。完整definitionId白名单、实际实例数和各国构成从运行配置写入文件，不只写“58张”。
- 使用冻结平衡规则：意大利陆军兵模5、建设海军5张、发起海战3张。其他数量也须导出实际值，不在回放时补默认值。
- 无7张手牌上限、12选7、常规摸牌及自主弃牌选牌；不自动补充资源。当前课程无序章和中立，开关明确为false。状态、响应等未纳入的牌不能凭正式卡表补入。
- A：全部剩余资源开放，使用和支付仍满足合法性。
- B：非基本剩余实例数N，均匀不放回开放K=min(N,max(6,ceil(0.6N)))；基本牌每类独立抽样一次，剩余≥4/3/2/1/0张时开放概率分别1/0.9/0.7/0.4/0，成功则该类全部剩余实例开放。
- 六国初始化各抽一次开放集合；首次进入自身回合不重抽，之后每个本国回合开始、选择之前刷新。周期内消耗只移除对应开放实例，不因数量跨档重抽；观察、恢复、响应、子效果、跨国援助和额外出牌均不刷新。
- 弃手牌/弃牌库顶均从整个剩余资源池等概率不放回抽样，包含未开放实例，排除已出来源牌、场上牌、结算中牌；指定类别费用只从符合条件实例抽。主动手牌费用不足不得发动；强制弃置及牌库顶缺额按冻结规则各自处理，不能混为一种不足规则。完整记录保存实际抽中实例。
- 钢铁条约special_227不加入。百团大战、湘西会战一次性：删除洗回分支及其费用，结算后进入资源弃置区，不重新开放。武器援助不抽牌，保留受援国额外出牌并使用其当前开放集合。
- 白色方案保留费用、征召、额外出牌；瑞典支援芬兰、维德孔·吉斯林发动政变保留条件及额外出牌限制。除明确覆盖外，不自行简化多动作事件。
- 法国资源归英国、中国部队不等于美国决策；百团大战属于苏联资源。回放分别展示资源所属国、部队国家和真正决策国。

resourceConfig使用带kind/version的结构化策略对象，当前基础定义见字段契约。特殊牌覆盖同时进入resourceConfig.overrides及catalog的实际文本/效果定义。未来新处理使用明确版本和命名空间；影响展示的新增结构须更新字段契约/requiredFeatures并共同验收，未知必需能力明确拒绝，不能猜测显示。

资源池模式必须显示“资源池”“本周期可用”“未开放”“弃置/消耗”，不显示不存在的手牌/摸牌库。不要用字段名hand碰巧存在于引擎内部，就把资源池当手牌显示。

## 5 规范化状态：stateSchemaVersion=1

start.state和每个frame.state至少包含下列信息。生产者可保留namespaced extensions，但客户端不能靠未约定扩展补齐下面的必需项。

### 5.1 公共游戏状态

- gameStatus：setup/playing/finished；round、phase、activeSeat；序章轮次/顺序与正式轮次分开。result在未结束时为null，结束时包含winner及victoryReason。
- completedCountryTurns：保留路径上的实际国家回合时钟；回退后恢复为目标状态值并截断后缀，新步骤再继续累计。不得把已撤销回合继续计入。
- scores：各国分数、双方总分、平局修正等实际计分项。
- units：unitId、country、type、regionId及当前补给/保护等可显示属性；各国兵模储备。
- regions：当前控制、有效大本营、对各阵营有效的补给点和其他动态修正。不能只用静态地图推测。
- prelude：是否启用/仍进行、紧张度、当前国家及初始化/收尾状态；未启用取null。
- neutrality：是否启用，美苏当前状态、已结束原因和事件引用；未启用取null。
- installed：状态、条约、暗置响应/军备的实例及可见数量；实例位置由cards/areas作为唯一归属真值，installed只是引用与效果元数据。
- flags：本回合/本轮使用次数、临时效果及其他会影响选择或后续结算的公开或私有规则事实。
- controllers：当前国家与controllerId映射；需要还原控制变化时保存binding和当前操作视角。视角不能替代真正decisionSeat。

### 5.2 卡牌实例与卡区

cards为实例字典：instanceId、definitionId、deckOwner、printedCountry、effectiveDefinitionRef（指向catalogEntryId）。名字相同的牌仍是不同实例；不要按中文名字合并。

areas为卡区数组，每区带areaId、seat、kind、ordered、cardIds。cards中的每个有效实例在该状态恰好属于一个实际卡区，包括结算中和移出游戏；不存在复制牌实例到两个区的情况。

standard卡区：regular_hand、regular_deck、regular_discard、active、face_down_response、face_down_armament、resolving、removed；启用序章时增加prelude_hand、prelude_deck、prelude_discard。牌库数组明确index=0是顶端。手牌数组记录实际逻辑/显示顺序，若二者不同须单独记录displayOrder且不影响牌效。

resource_pool卡区：resource_pool、resource_discard、active、face_down_response、face_down_armament、resolving、removed，以及课程实际支持的其他区。首批没有的区可为空，但不能假冒正常牌库。资源池无战略牌序，ordered=false；为复现随机抽样，可在随机记录或原生检查点保存内部候选顺序。

资源池另有availability：各国cycleId、refreshAt、openInstanceIds、剩余总数和开放数。openInstanceIds是resource_pool子集，不是第二个实际卡区；未开放=池内减开放。A也明确写全部剩余实例开放。

序章亮顶是prelude_deck[0]的知识/显示投影，不复制到序章手牌区；UI可以在手牌栏上方标为牌库顶。

### 5.3 决策与结算上下文

- pendingDecisions：尚待回答的决策快照数组；即使当前只有一个，也用数组。包括决策者、提示、触发原因、合法选项、约束、已预选内容等，详见第6节。
- resolution：当前有效帧栈/队列、frameId、parentFrameId、来源卡/国家、当前子效果、尚待执行的完整效果序列、已绑定的真实目标/单位、步骤完成/取消状态、窗口开放/关闭状态。
- 禁止只保留当前最内层frame而丢掉父事件尚未执行的效果。选过的目标、次数、顺序和“只允许刚建部队”等限制必须具体化，不只是一个true标志。
- notifications：当前仍应显示的提示、触发事件与接收座位。“知道了”通常不是规则决策；若确认会推进翻牌或结算，则必须按真实规则节点记录。

### 5.4 可见性：还原当时看见的内容

全量档案保存真实状态，用于全知回放；还必须保存knowledge投影，支持按当时国家视角回放。

knowledge按public、六个seat分别记录：允许知道的卡牌身份、各区可见数量、可见顺序/可见前缀、已知但不在手中的牌、可见决策/选项与提示。每条可见信息有对象引用及scope，不能只给一个“这个国家可以看所有自己的牌”的总开关。正常玩家通常不能看自己牌库全部顺序。

暗置牌对别人可见的只有数量/类别等实际公开信息，不输出可关联的真实instanceId。已知牌被洗混后，应记录顺序知识失效；不要用终局信息倒推早期可见性。资源池B的对手开放集合同样不在对方视角显示。

客户端提供全知/各国家/公共视角，必须使用记录中的知识投影，不直接把全量对象传给有限视角组件。事件、cause中的卡牌引用、选项label、通知和结算栈也必须同步过滤；不允许只把卡面盖住却从提示中泄漏名字。私有对象默认不显示，仅投影明确授权的信息可见。全量档案本身仍包含秘密，不能靠前端遮盖声称它是保密文件；现场只读客户端不应接收整份全知档案。脱敏导出属于另一个受限档案能力，必须标明不支持全知完整复现。

### 5.5 与原生引擎状态的关系

规范化state负责独立显示；可另附engineCheckpoint用于匹配版本的规则复算或从此续玩。engineCheckpoint需有引擎状态schema和构建指纹，不作为跨版本UI的唯一数据来源。effectDefinition/definition等Json字段只保存有类型标记的规则数据，至少包括动作种类、国家、完整目标限制、次数、顺序、费用、条件和绑定；禁止只塞一段描述文字冒充完整效果。

只实现事实回放时engineCheckpoint可选。若宣称可续玩/规则复算，则起点及所需边界必须包含完整原生规则状态、随机流和原生命令映射；缺失时客户端明确不提供该能力。

## 6 每一次决策必须怎样记录

每个决策有唯一decisionId，包含：

- activeSeat、decisionSeat、controllerId、sourceSeat、unitCountry，分别表示当前回合、决策归属、操作者、效果来源和部队国籍。
- sourceCardInstanceId、resolutionFrameId、effectId、triggerEventId，以及为何出现本次询问的结构化cause。
- decisionKind，例如play_source、target、ordered_targets、branch、response、air_defense、pay_cost、discard、keep_opening、extra_play、end_phase、confirm_effect。
- prompt用于中文显示；结构化cause必须说明攻击国家、被攻击国家、地区和战斗类型等，不能只存“是否响应”。
- options：稳定optionId、显示label、语义payload。地区/卡牌/单位必须用稳定ID引用，不依赖字符串猜测。
- constraints：min/max、是否允许skip/cancel、是否有顺序、互斥或绑定条件。大组合可记录合法基本选项和明确约束，不必枚举指数级组合；前一步选择改变合法性时建立下一决策。
- selectedSoFar：当前预选/承诺集合及顺序；真正提交前不能把预选当作牌已打出。

在第一次接收答案前，必须已有一个状态含完整pendingDecision。不能先执行再回头拼凑曾经有哪些选项。

答案frame的action保存decisionId、optionIdsOrdered、语义selection、actor/controller和提交原因（user/ai/timeout/autopolicy）。多目标攻击、重建顺序、支付组合等保留有序内容，不转成无序集合。skip、decline、cancel分别表达，不统一写“空数组”。

默认或自动唯一选项若影响规则，也要记录为自动决策，automationReason明确为forced_single_option等；不伪称人类/模型主动选择。非法/过期命令仅可写诊断，不进入成功游戏frame序列。

“国家A打牌使国家B选择，中国部队执行”的三种身份必须保留。多国绑定同一人也不得把所有decisionSeat合并成一个国家。

## 7 frame：原子事实与因果链

frame必需字段：recordType、seq、beforeStateSeq、timelineId、kind、cause、events、state；kind为decision/random/automatic/control之一。按种类增加action或randomResult或control。

cause包含transactionId、rootActionId、parentEventId、resolutionFrameId、effectId和sourceCardInstanceId；不适用项显式null。一次外部命令可能产生多个frame，它们共享transactionId，但不能把命令重复视为执行多次。

events每项至少有eventId、eventType、actorSeat/sourceSeat、对象引用、cause、visibility、outcome及必要before/after值。eventType字典首版至少覆盖：

| 类别 | 必须能表达 |
| --- | --- |
| 决策 | 决策打开、提交、拒绝分支/跳过、取消 |
| 卡牌 | 宣告打出、支付、区域移动、安装/暗置、牌自身效果完成、最终入弃牌或移除 |
| 子效果 | 宣告、应用、完成、无合法目标略过、被取消；多次相同效果仍有不同effectId |
| 战斗 | 发起、攻击/防守对象及地区、响应/防空、结果、移除或保护 |
| 场面 | 建设/征召/移动/移除、补给变化、控制变化、动态补给点和大本营变化 |
| 规则进度 | 阶段/回合/轮次开始结束、序章紧张度与结束、中立结束、计分明细、胜负 |
| 资源与随机 | 摸牌、弃牌、洗混、随机支付、资源开放刷新和失效 |
| 控制 | GM修改、控制者变化；回退采用截断，外部读档及从回放另开对局采用新建记录，不伪造对应control frame |

不得只在一个玩家选择前后各截一次图。一个选择触发的自动连锁也必须有独立可停留的节点，至少在每个规则子效果完成、每次卡区移动/支付、每次随机结果、每次窗口开闭和阶段/回合切换边界记录。

若一个引擎调用内部连续完成了建设、对手消灭、后续攻击，记录钩子必须进入结算器捕获这些边界；仅在arena.step返回后看最终状态，会丢掉中间事实。不要通过最终状态差分猜发生过什么。

一个frame可包含不可分割的同一规则原子操作产生的多个事件，例如同一次卡牌移动同时更新两个区；不能把多个有独立时点或可被响应的子效果合并成不可观察的一团。

原生命令只附在transaction的发起记录上，后续自动frame引用transactionId。事实回放读state；可选规则复算按transaction重执行一次，并在对应结算钩子比对各frame，不能按每个子frame重复执行原命令。

## 8 随机结果：记录事实，不重新抽签

每次随机操作保存randomId、streamId、算法/版本引用、目的、发生于哪个effect/decision、抽样规则、候选域及结果。大量候选可引用beforeState中的有序ID列表，不能引用会变化的“当前牌库”。

- 洗牌：记录洗后的完整实例顺序，不能只写“洗混成功”。
- 发牌/抽牌：记录移出的具体实例、来源位置及目标区；普通按顶抽牌也记录实际移动结果。
- 随机弃置/支付：记录被抽中的实例、有序结果、费用类型及是否满足全额；禁止回放时重抽。
- B资源开放：记录每国cycleId、刷新前池、基本类数量和判定结果、非基本抽中实例、最终openInstanceIds。
- 随机种子/随机分座位：若在记录覆盖范围内，保存实际结果。
- AI策略采样：实际选择本身必须记录；策略随机流、概率可附诊断，回放不加载模型重采样。

如支持原生复算，再记录各随机流操作前后状态或检查点。不同用途流须独立标识；不能用唯一seed假装已经记录全部随机信息。

随机private结果归全量档案，国家视角按knowledge过滤。记录器能读真值不等于AI观察可读真值，两条通道分离。

## 9 初始化、回退、读档与分支

### 9.1 从创建开始

origin=creation必须覆盖第一次会影响局面的初始化操作之前的起点，之后逐项记录洗混、初始部署、发牌、初始状态、序章弃两张/摸两张/亮顶、资源池初始化和B首次开放等。第一次正式进入本国回合未刷新也应与已记录cycle保持一致。

若现有代码只拿得到初始化后的状态，可把它作为snapshot起点并明确“初始化过程未记录”，不能宣称完整从创建复现。最终应把记录器接到初始化之前。

### 9.2 回退：仅保留最终有效过程

本版采用truncate_on_undo：回退时删除目标快照之后的全部记录，不追加undo控制节点，不保留已放弃分支。一次用户操作可能对应多个子效果、支付、随机和响应frame；不能只删最后一行，也不能凭文本判断删几行。

主机保存存档/回退点与精确state seq的映射。成功回退后，以该目标start/frame为最后状态，截断所有后续记录（包括end）；recordingRevision加1，后续从目标seq+1追加。保留前缀的事件引用必须仍然有效；废弃后缀的异步写入、事件、提示和旧决策请求不能重新写回。计数、索引及导出哈希重新计算。该文件只承诺复现保留路径，不承诺复现被撤销的尝试。

回退状态恢复与日志切换作为同一主机事务处理。采用临时文件及原子替换或等效可靠方案；失败时不能出现“游戏已回退而日志未截断”的可继续运行状态。已下载的旧文件不修改；因recordingRevision不同，不与新路径混淆。正常逐行追加不增加recordingRevision。

### 9.3 读档、GM修改与另开记录

从当前文件可定位且验证相同的存档读回，按9.2截断。读入无法与当前保留前缀准确对应的外部存档时，新建独立记录，origin=snapshot，注明来源与起点；不得伪造该存档之前的操作。原文件封为interrupted/partial后保留，不覆盖。

GM修改及控制者变化继续追加control frame，保存操作、完整后状态和原因。新格式Control不包含undo/load_save；这些操作分别采用截断或新建记录。每个文件使用一个timelineId，截断不新建分支时间线。

从回放节点另开对局必须另建matchId/recordingId，origin=snapshot，并保存parentRecordingId、parentRecordingRevision、parentSeq；只读回放本身不提供直接改原局能力。原生续玩不是首版必需能力。

房间重连不重复执行旧动作。服务器是唯一排序与写入源；追加请求按recordingId、recordingRevision及eventId去重，过期修订拒绝。单机/训练端由唯一竞技场实例负责。

## 10 end与完整性检查

end必需：seq、lastStateSeq、recordingStatus、stopReason、gameStatus、winner、victoryReason、finalScores、frameCount、decisionCount、prefixSha256。

recordingStatus可为complete或partial；stopReason包括natural_game_end、export_while_playing、training_truncated、interrupted、snapshot_segment等。记录正常封口不等于对局自然结束。中途导出必须显示“截至此处”，不得补一个赢家。

prefixSha256计算从文件第一个字节到end行之前的全部原始UTF-8字节（含每行LF），不包含end行。读端对原始字节校验，不能先JSON重排再算。这样不依赖各语言浮点/键排序的重序列化差异。哈希用于损坏检测，不是作者身份签名。

没有end、尾行不完整或哈希不符的文件不能标为完整。可尝试恢复连续可解析前缀，明确提示缺失范围，并禁止声称完整终局或规则验证成功。

导入时检查seq连续、引用有效、国家/地区/卡牌ID存在、实例唯一归属、开放集为池子集、状态衔接、事件和选择对应、结束统计与最后state一致。能力字段为true却缺数据应拒绝该能力，不能静默猜。

## 11 客户端回放行为

必须提供按决策、子效果、国家回合/轮次移动，暂停/自动播放/向前向后/跳至指定节点；倒退直接加载目标完整state，不调用“反向执行牌效”。

右侧详细记录点击决策条目时，默认加载显式decisionBeforeStateSeq指向的提交前完整状态，展示当时的问题、触发原因、合法选项、已预选内容，并将实际答案单独标为“最终选择”。decisionBeforeStateSeq必须等于该答案frame的beforeStateSeq，该状态必须含对应完整pendingDecision。接受答案之前最后一次候选变化也必须先落状态，不能拿更早菜单代替。条目可切换“选择后”，加载答案frame.state；继续前进查看后续子效果。带action的自动决策同样需要decisionBeforeStateSeq。普通子效果条目默认显示其后状态。回放中不能让观众的点击修改原局；“尝试另一选择”必须另开分支且需要匹配规则引擎。

卡图、文本、类别、国家色使用文件catalog快照及版本化asset引用。卡图缺失时用文本卡替代，不影响逻辑回放。区域地图美术缺失时可用结构化布局降级；不从不可信文件执行脚本。文件内图片/链接只作为受控资源，不作为规则代码。

standard显示对应手牌/牌库/序章区；resource_pool显示资源与开放状态。按真实阶段隐藏不存在或已经结束的面板，但历史跳回时应恢复显示。切换模式只读header，不靠有没有hand字段猜。

国家视角正确处理序章亮顶、暗置、私密弃牌、响应提示与对手开放集合。提示中应可点击来源卡、地区和部队，利用结构化引用完成索引，避免对中文字符串做全局替换。

事实回放成功、文件完整性通过、匹配引擎规则复算通过，三者分别显示。正式模式仅允许gameVersion与客户端相同的文件导入；训练资源池不比较生产程序版本或游戏版本，先检查formatVersion、schema和requiredFeatures。通过兼容校验后，仅靠快照回放，不拿当前规则执行旧命令。旧协议如需迁移必须显式转换，不能直接按v2读取。

requiredFeatures必含`qm.fact_state.v1`、`qm.knowledge.v1`，并按模式包含`qm.standard_areas.v1`或`qm.resource_pool_areas.v1`（两者不同时要求）。新增会影响完整展示的字段能力以新ID声明；仅需展示的规则覆盖若已能用现有状态/卡表表达，不必为每一张牌发明功能ID。可忽略的诊断扩展不放入requiredFeatures。

### 11.1 界面要求

导入回放后，右侧原“对局记录”替换为“详细对局记录”，沿用最右侧纵向布局及六国信息入口。每条记录可以点击定位；提供起点、决策、子效果、国家回合/轮次导航及前后切换。允许将自动步骤折叠显示，但必须能展开和定位，不能省略原始数据。

点击条目后，地图、分数、回合、手牌、牌库及顺序、弃牌、序章区、响应/军备、状态/条约、兵模和六国详情统一取所选快照，不能部分仍引用实时对局。全知视角允许查看全量卡区；国家/公共视角严格用knowledge过滤。界面本地展开状态可保留，但显示内容必须全部刷新到同一节点。

资源池模式替换相应区域为资源池、本周期可用、未开放、弃置/消耗；不能伪造手牌和摸牌库。保留六国详情，按记录实际数据展示数量。回放使用独立只读状态容器，不发送打牌命令、不推进结算、不弹出必须回答的现场响应、不改变当前联机对局。退出回放恢复原对局界面。

### 11.2 主机保存、导出与发布包

每个发布压缩包新增空目录“对局记录”。打包工具须保留目录条目；不得把开发者的真实对局、测试日志混入发布包。服务端以发布程序目录为基准解析该位置，不依赖启动命令当前目录；浏览器无主机文件系统权限时应由现有本地主机服务承担写入。

每局独立文件，建议以安全的创建时间+recordingId命名，不直接拼接未经清理的用户名。主机持续保存UTF-8 JSONL，普通步骤逐行追加，回退按9.2原子截断。活跃文件可以尚无end；自然结束后补end封口。崩溃恢复只接受完整且已验证的行，不把断裂尾行当成成功记录；错误须可见，不能静默丢历史后继续声称完整。

用户点击“导出对局记录”后，服务端获取某个确定修订和最后seq的一致快照，按第10节生成完整文件（中途导出stopReason=export_while_playing），通过浏览器普通下载交给请求者，不要求持续修改用户文件的权限，不产生0KB占位文件。导出副本的end不追加进仍在运行的主机文件；导出期间发生新步骤或回退不应混入已确定的下载快照。允许流式传输，但传输内容必须来自固定快照。

导出沿用产品已有访问权限，本规范不新增“仅GM可导出”等限制。full_fidelity下载包含所有国家秘密，即使播放器选择国家视角也不改变文件含有全量数据这一事实；开发说明须明确这一点。若以后要做对局中保密导出，应另定脱敏格式/能力，不能将它冒充全量回放。

## 12 训练端记录职责与性能

训练采样统计与完整回放档案分开。trace=summary、现有step前后单位/分数日志、PPO观察张量都不是完整回放文件；只有按本规范导出的full_fidelity档案才可作为客户端完整回放输入。

必须记录所有国家的真实选择、自动选择和自动结算，不只记录正在训练的国家或有梯度的样本；不能因为单选节点不参加策略损失就不记录。

不要为了导出改变环境随机调用顺序、开放刷新时机、结算顺序或策略采样。开启/关闭记录，同种子和同选择序列的游戏结果应相同。

完整记录有额外成本，不要求所有百万级训练步都输出完整档案。训练者可以配置选定评估局/抽样局/异常局的完整记录。被选中的局必须从创建前开始捕获；训练中途才开启只能标snapshot起点。可用磁盘流写与压缩，避免把全局历史复制进每个state。

state只含当前有效规则状态和知识，不嵌入累计publicLog/events/records/recovery，否则文件会平方级膨胀。过去事实只在前面的frame中；当前仍在结算的因果引用必须保留。已结束框架可留摘要，不复制全部旧事件。

AI诊断放在frame.aiDiagnostics：policyId/版本、原始候选语义ID及概率、被选概率、价值等；训练后才有的优势/回报不要回写已哈希封存的原文件，可另附以recordingId+recordingRevision+decisionId索引的诊断侧文件。诊断不是回放必需，缺失不影响还原选择。

## 13 旧格式迁移

旧客户端quartermaster-replay v1在匹配旧引擎下可以尝试转录为本规范；转换器须报告能恢复哪些初始化/决策/自动时点。若旧文件没有原选择菜单、随机中间结果或原规则版本，不能推测补齐再标full_fidelity。

旧AI summary/full日志目前不能仅凭名字叫full就判为完整。只有单位/分数前后值，没有卡区/开放集合/中途选择和自动结算时，不支持完整转换。可标为旧版摘要播放，或有完整匹配原生快照和可复现命令时重跑转录，再明确标识“经复算重建”与验证结果。

最稳妥交接顺序：双方先实现本规范的最小完整文件与公共校验器，交换同一批样例验收，再做高级UI和大规模记录优化。

## 14 双方必须共同通过的验收用例

1. 正常对局：初始化、12选7、普通事件、弃牌和摸牌，逐决策/子效果前进后退一致。
2. 序章+中立：初始化弃摸亮顶、紧张度、历史入弃牌、条约保留、结束序章、美苏结束中立及通知。
3. 连锁：建设→湿地泥沼→后续状态机会；攻击→父卡完成→破译密码机会。逐点可见而非只剩最终场面。
4. 多动作事件：阿登前后两步；巴巴罗萨有序预承诺；百团大战绑定刚征召陆军；重建收回后逐支建设。
5. 资源池A：一次性事件使用、随机支付、资源减少，无虚构手牌/摸牌。
6. 资源池B：首轮初始化、后续各国独立刷新、未开放资源被弃、援助不重抽、对手视角不泄露开放集合。
7. 同人多国/跨国援助：回合国家、决策国家、操作者和部队所属国均正确。
8. 显式拒绝响应、跳过、取消、自动唯一选择均可区分；选择菜单、理由和真实答案完整。
9. 随机结果：同一个文件多次播放和不同客户端播放，洗牌/支付/开放结果完全相同，无需重新随机。
10. 回退精确截断：一次操作多frame全部按目标快照截断；修订增加、引用无悬空、旧异步写入拒绝；前缀保留且后续可正常追加。外部存档另建snapshot记录，GM修改追加后状态。
11. 版本策略：正式对局同游戏版本可导入，不同版本拒绝；资源池不同生产/游戏版本但协议及必需展示能力匹配时可展示；未知必需扩展明确拒绝，不偷偷套正式规则。
12. 文件损坏、中途导出、训练截断、断线恢复、缺end：明确完整性状态，不伪造赢家。
13. 卡区/单位/分数/控制/知识等每个frame的显示与生产者当时状态一致；不能只比较最终赢家。
14. 记录开启/关闭规则结果相同；完整记录流写不向AI观察泄漏全知信息。
15. 点击决策默认还原提交前，选择后可切换；六国卡区、信息栏和地图同步切换，无实时状态串入。
16. 发布包空目录存在；主机追加、回退原子替换、并发导出固定快照、普通浏览器下载及主机中途继续记录均通过。

客户端开发者交付：导入/校验、事实播放器、双模式视图、知识投影、时间轴、卡牌索引、截断历史、主机落盘与下载及测试。

训练端开发者交付：标准导出器、结算内记录钩子、模式配置/实际卡表快照、随机与开放记录、截断封口、无副作用测试，以及A/B各至少一份完整样例。

双方共同交付：standard与resource_pool同一格式的可解析样例、字段schema/校验器和上述跨端验收结果。不得各写一种结构再让客户端按文本猜含义。

## 15 最小结构示意（非可导入样例）

下面省略了必需状态字段，仅说明封装关系，不得直接把省略版作为导出实现。

```text
header(seq=0, format=quartermaster-match-log, formatVersion=2,
       mode=standard|resource_pool, rules, resourceConfig, catalog, map, ...)
start(seq=1, state=初始化前完整状态)
frame(seq=2, kind=random, beforeStateSeq=1,
      randomResult=本次实际洗牌/开放结果, events, state=操作后完整状态)
frame(seq=3, kind=automatic, beforeStateSeq=2,
      events=[decision_opened], state=含完整待选问题的状态)
frame(seq=4, kind=decision, beforeStateSeq=3, decisionBeforeStateSeq=3,
      action={decisionId, optionIdsOrdered, selection, actor}, events,
      state=接受选择后的完整状态)
frame(seq=5, kind=automatic, beforeStateSeq=4,
      events=[effect_applied, effect_finished], state=子效果结束后的完整状态)
...
end(seq=N, lastStateSeq=N-1, stopReason, winner, finalScores,
    frameCount, decisionCount, prefixSha256)
```

本规范的首要验收标准是：**第三方仅持文件、地图/卡牌展示组件和本格式解码器，不运行原模型、不重新抽签、不强行调用新版规则，也能完整浏览每个已记录抉择及其真实后果。**
