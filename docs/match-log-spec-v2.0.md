# 战场军需官回放规范 v2.0：动作增量与每轮检查点

日期：2026-09-30。状态：用户最新裁定；v1.7.1 的实现和验证边界见 match-log-validation.md。

本规范完整替代v1.0/v1.1的“逐frame全量状态、独立事实播放器”路线。首要目标是当前版本正式对局的紧凑回放。文件协议继续用quartermaster-match-log，formatVersion升级为3；recordingModel固定为action_replay。不得把旧formatVersion=2的全量日志直接改版本号冒充新格式。

运行时契约：`src/actionReplay/contract.ts`；运行时校验器：`src/actionReplay/codec.ts`。原 `src/matchLog` 仅保留历史协议工具，不是新客户端的导入入口。

实现参考为1.6.11发布包中的初始状态+命令重演路线，核对结论见配套《v1.6.11回放核对与迁移说明》。沿用其规则引擎能力，不直接沿用旧的逐命令条目、回放写入实盘存档、弱版本检查和回退追加restore快照的行为。

## 1. 核心原则

1. 开始记录时保存一次完整、可恢复的当前全局状态。以后以完整动作和实际选择为增量，由匹配版本的引擎推导场面。
2. 正式开局及每一轮结束保存完整检查点，序章中间不保存。禁止逐动作、逐子效果保存全量场面。
3. 一张牌的打出/发动、费用、目标及正常结算合为一个动作条目。自动连锁中没有独立主动发动的内部步骤不单列。
4. 插入且实际发动的响应另显示一个动作条目，保留其父动作和插入时点。未发动的可选响应默认跳过，不生成逐个拒绝/窗口关闭记录。
5. 每次实际洗牌额外保存一条shuffle记录，包含洗后完整实例顺序。仅保存种子不满足此要求。
6. UI、提示、通信和存档元数据不得被误认为规则动作。无效果的点击、预选、拖动浏览、点击“知道了”和查看其他国家不产生动作条目。

这次变化明确放弃“没有原引擎也能独立复现全部中间事实”的承诺。协议优先保证同版本游戏的动作回放，不为未来任意训练变体保存通用全量状态。

## 2. 检查点的准确位置

“一轮”是德国、英国、日本、苏联、意大利、美国全部完成各自正式回合；不是每个国家结束都存一次。

| 存储点 | 要求 |
| --- | --- |
| 初始状态start | 新局完成实际初始化后、任何玩家实际操作之前：已发出的常规手牌、实际牌库顺序、初始单位、规则开关、序章起始手牌/牌库/亮顶等全部保存；未启用序章则是起手选择前。无需反演初始化前的洗牌过程 |
| 正式开局formal_start | 序章结束并且六国12选7全部完成后，德国第一次正式行动/选择之前；不开序章同样存在 |
| 每轮结束round_end | 美国本轮回合收尾、计分/胜负及本轮其他必须完成的结算结束后，下一轮德国开始任何行动或选择之前。完整经过第1轮至第20轮，就各保存对应检查点 |

通常完整20轮最多为start+formal_start+20个round_end，共22份；提前结束则更少。不要同时存“美国结束”和“下一轮德国开始”两个重复点。终局发生在轮末时复用该轮末检查点，不额外保存一份终局全量。

序章只有start，没有序章每国/每轮检查点；中途查看序章从start推导。不得再沿用“只在第5/10/15轮存”的旧讨论方案。

定义边界时禁止依赖UI显示的round数字猜测。记录明确的completedRound；轮末检查点可处在尚未触发下一轮开始效果的稳定边界，恢复适配器负责从该边界继续。若现有引擎自动推进下一轮，应在自动推进前加检查点钩子，不能等德国已做选择再补存。

完整检查点保存规则状态、所有卡区及顺序、单位/分数/持续状态、知识信息、待决策上下文、随机流、ID计数器等恢复所需数据。**不保存累计日志、旧回放、旧存档、旧检查点或缓存副本**，否则会重新产生平方级膨胀。检查点可以压缩，不准为了恢复方便额外嵌套一整份历史。

## 3. 版本与训练兼容

header包含gameVersion、engineFingerprint、replayAdapterId/version、commandSchemaVersion、checkpointSchemaVersion、规则开关/规则配置指纹、recordingId及recordingRevision。

正式对局导入要求游戏版本匹配，且匹配的回放适配器能够解释该引擎/命令/检查点版本。禁止仅同为“1.7”就用不同结算引擎强行回放；不匹配明确拒绝或要求对应版本。

卡表、地图及规则定义由匹配游戏版本提供，不再每帧或每局内嵌完整卡表/地图。文件只记录必要配置及数据指纹。文件不携带可执行脚本，不能下载并执行任意“适配器”。

训练mode=resource_pool时，必须有本地已实现的训练回放适配器，理解对应的规则基线、课程覆盖及资源池结构。仅生产程序版本不同可允许，但必须确认适配器与实际语义匹配。不能继续承诺只要有通用schema就支持任意训练规则。没有适配器则明确不支持；不把资源池画成手牌。

第一阶段资源规则仍按冻结训练方案：四基本牌/58事件、A/B开放、随机费用、一次性百团大战/湘西会战、武器援助不抽牌等。配置只在header中声明一次。训练没有12选7时，formal_start表示初始化后、首个正式决策前；若与start相同，只写已有检查点的引用，不重复存完整状态。未来变体的随机开放/费用可用compact random_result记录实际结果，不按每次决策全量保存。

训练头必须给出确切课程ID/版本、白名单ID、已采用平衡配置、A或B及开放参数、费用抽样规则ID、覆盖规则ID和指纹。钢铁条约不在白名单；百团大战/湘西会战移除洗回分支；武器援助只移除抽牌，保留受援国选择额外出牌。资源剩余/已消耗/当前开放分别展示；不能从剩余数量猜开放集合。A默认全部开放，B按冻结方案在各国回合开始刷新。实际B抽样和随机支付结果用独立随机记录还原，不输入策略观察。此协议不改变训练规则。

## 4. 完整动作的边界

动作是一次实际打牌、主动发动、响应、实际支付并执行的选择、起手留牌、主动弃牌、资源重整、编辑器修改等规则事务。一个动作的目标选择、费用选择和同牌多个子效果选择保存到该动作内部，不拆成独立可浏览条目。

### 例一：正常建设

德国打出建设陆军，在东欧建设：一条动作，内部保存卡牌实例、决策国、部队国籍、目标东欧。无需“打牌”“选择地区”“建设成功”三个条目。

### 例二：主动连携

德国发动兵贵神速，选乌克兰目标并消灭苏军：一条新动作。兵贵由玩家另行主动发动，所以与此前建设分开；攻击声明、防御检查、消灭结果不再各写一条。

之后德国未发动闪电战：不写条目，不保存闪电战的拒绝菜单或完整局面。

### 例三：插入响应

兵贵发动后英国实际发动保持冷静：英国响应是独立动作，保存其来源、费用牌和取消目标，明确插入兵贵的开始生效前时点。父动作被取消后的显示为“兵贵神速被保持冷静取消”，不得同时写成已消灭乌克兰苏军。

记录必须在回放到正确窗口时插入英国响应，再继续/终止父动作，不能先让父动作完整攻击后再补响应。若英国未发动，则回放直接按默认跳过继续。

### 自动与主动

自动且确定的计分、补给、费用后续、弃牌入区、无合法目标略过、必然触发效果，由引擎推导，不另存场面。若自动效果要求玩家做有意义的选择，该答案嵌入所属动作；独立阶段上产生且没有所属动作的必选决定，可形成一个阶段动作。

玩家“不做某事”却会改变状态时不能一概丢弃。例如放弃出牌扣分、弃0张扣分、支付/拒绝费用导致攻击停止，需要保留其语义：优先作为所属动作的分支选择；若独立发生则是阶段推进动作。它们不是“未发动的可选响应”。不要把实际后果删除。

## 5. 默认跳过未记录的可选响应

**可以且应当采用：已完成动作范围内，没有明确记为发动的可选响应全部跳过。** 不保存每个未发动窗口、逐座位拒绝、canSkip菜单或closed标记。

回放适配器遇到可选窗口时：

1. 检查该动作/子效果/时点是否有记录的实际响应；有则按记录顺序执行。
2. 没有则选择规则允许的跳过，继续自动结算；不能再次弹询问等待观众作答。
3. 同一时点多个响应依实际顺序执行，每次按引擎重新检查合法性。显式记录的响应如今不合法，视为版本/记录不一致并停止；不能把它静默变为跳过。
4. 必选目标、实际费用、必选分支不能按这个规则猜答案。缺数据则报错，不猜“第一个合法目标”。

只为实际发动的响应保存定位锚点：父actionId、稳定effectPath、timing及occurrence。effectPath表示同一张牌中的第几个有序子效果；occurrence区分重复攻击/重复窗口。运行时随机生成的窗口ID或中文牌名不足以定位。无需保存未发动窗口列表。

中途导出时，未回答不等于拒绝。若当前动作未完成，仅保存一个pending动作组及其当前frontier（未解决决策的稳定定位），回放在frontier停止，不对它及其未来窗口自动跳过。已完成动作组不含frontier。这里记录的是当前录制截止点，不是逐窗口关闭历史。

## 6. 磁盘表示与界面条目

UTF-8 JSONL。记录类型：header、start、action_group、shuffle、random_result（如需要）、checkpoint、end。所有行seq连续，只有start及存有新快照的checkpoint携带完整state。

一个action_group对应一个顶层完整动作及其嵌套插入响应。root与每个intervention都有独立actionId，动作自己的choices按实际选择顺序保存。插入响应使用递归结构，避免同一选择同时复制到父子两处。

每个选择和插入动作均带稳定锚点及组内order，按实际发生顺序编号；不能仅用“父选择数组在前、子响应数组在后”决定执行顺序。实际主动连携即使仍处在同一引擎调用栈中，也有独立actionId与界面条目，可以作为组内嵌套动作保存。自动推进的阶段收尾用phase_advance组承载有后果的选择/随机性与边界，UI不需要展示无信息的空白推进条目。一个组不得跨过formal_start或round_end检查点边界；适配器应在边界暂停推进、封口，再生成后续组。

**磁盘一行与界面一行不是同一个概念。** action_group在磁盘按一个紧凑事务保存，UI展开成“父动作一条、每个实际插入响应各一条”。因此英国保持冷静仍单独可点击；目标/费用等不是额外界面条目。响应自己被其他响应打断时同样递归。

父动作可以在子响应之前显示发动，但结果只能显示实际最终结果。点击父动作可看动作前/整个动作组结束后；点击响应看插入前/该响应结束后的推导状态。未插入响应时只有原动作一条。普通自动子事件不提供逐个持久化节点。

录制过程中允许使用只含命令/选择的临时事务日志，防止动作尚未结束时掉线丢数据；不能借此保存每个子步骤全量状态。动作完成后写定稿组；中途导出把临时数据封成pending组。历史预选和无效命令不属于成功动作。

动作组末尾可以保存固定长度的状态摘要哈希用于验真，不保存afterState、beforeState、全量候选菜单、模型向量或所有合法动作。UI文字由版本匹配的引擎推导；可缓存少量summary但不能用于驱动结算。

状态摘要使用适配器定义的规则状态投影，排除网络revision、展示视角、通知已读、累计显示日志等非规则字段，但不能删除影响规则的已触发次数、历史事实标记或待结算栈。规范化版本应固定对象键排序、数组保序、数字/字符串序列化和UTF-8编码；同一版本录制与回放必须共用该实现。文件完整性哈希另对end之前的实际行字节计算，不能与规则状态哈希混用。全量检查点也应通过专用序列化器导出，不得直接JSON.stringify整个Session。

## 7. 洗牌与其他随机性

每次shuffle记录至少包含：shuffleId、所属groupId/actionId、发生的effectPath/occurrence、牌库所属国/卡区、洗后完整且有序的cardInstanceIds、执行后的随机流状态（适配器需要时）。使用实例ID，不是可能重复的卡名。

shuffle行是独立磁盘记录及可显示的洗牌条目。回放到该确切位置时注入记录顺序，不重新随机洗牌。必须验证洗前/洗后实例集合一致；新加入牌先完成对应移动，再验证。完全相同的重复牌也保留实例身份。

洗牌可能发生在尚未完成的动作组内，允许shuffle行先追加，动作组定稿后通过groupId/actionId引用。存储seq是文件顺序；洗牌的执行位置由动作锚点决定，不能按文件行先后提前洗牌。封口前检查所有引用；游离随机记录不能被静默执行。

初始实际牌序已在start中；start之后任何洗牌都必须记录，包括资源重整、检索后重洗。单纯抽顶牌由当前牌序推导，不额外复制剩余牌库。

非洗牌随机结果如随机弃牌、B课程开放，优先保存小体积的实际结果与锚点，或使用明确可复现的独立随机流契约。不能使用Math.random/墙钟而不记结果。随机流恢复/推进必须一致，注入洗牌顺序后不能导致后续随机序列错位。

## 8. 导航、恢复与兼容

点击动作/响应时，从目标之前最近的start/checkpoint恢复，按顺序执行其后动作组，必要时执行到目标组中的锚点暂停。不能用目标之后的轮末检查点来展示目标之前。

引擎以回放模式运行：禁用网络发送、自动存档、回放再次录制、弹出交互等待等外部副作用，保留真实规则。退出后恢复实时游戏，不污染当前房间。

回放显示于地图右侧，替代常规记录区域，保留六国详情及视角查看。默认点击显示该动作作出决定前的局面，另提供查看结算后；插入响应的“前”是它实际插入的局面。回放会话独立于正在进行的房间，导入/跳转/切视角不得经过正常游戏commit写盘。网络修订号、UI视角、通知已读状态不作为重演命令前提；适配器为内部transition提供当前有效上下文，不照抄旧expectedRevision。必要的规则性确认应由回放适配器自动执行，真正有选择的翻牌处理仍记录答案。

引擎推导出所有卡区和知识状态，因此手牌/牌库/六国详情仍能恢复；国家视角仍用当时知识过滤，全知视角看全部。不得因为用了增量而只恢复地图单位。

支持按序列加载检查点、按动作/轮定位。播放器可以在内存缓存最近推导状态加速反复跳转，但不把此缓存写回档案，不在内存为全部动作永久缓存全量历史。检查点之间回放工作量受一轮限制；序章从start推导。

同版本不能保证数据绝对正确。到达检查点应可比较推导状态摘要；不一致报告第一个可定位的动作/检查点，不能静默加载后续快照掩盖错误。检查点存档自身也须验证完整性。

## 9. 回退、读档与文件保存

继续采用主机固定“对局记录”目录和浏览器下载。每局独立文件，导出固定修订的稳定副本，追加end及哈希；不产生0KB占位，不反复申请修改下载文件权限。

回退删除目标之后的动作、附属洗牌/随机记录和检查点，增加recordingRevision，不保留撤销分支。如果回退落在动作组内部，须裁剪该组到准确前缀，变为pending并更新frontier，不能误保留被撤销的目标/费用/响应。之后重新完成动作。主机游戏状态和日志截断作为同一事务处理。

读入无法与当前前缀匹配的外部存档，另建origin=snapshot的记录，以该存档作为新的start；不伪造更早历史，也不在同文件偷偷增加一个任意时点全量检查点。这个新文件只声明记录从此处开始。

场景编辑器的实际改动保存可解释的编辑命令及值，不追加整局快照；若无法增量表达，可明确开启新的snapshot记录会话。控制者/视角信息只保留影响操作身份的部分，不记录心跳、连接秘钥、聊天和无关UI状态。

运行中的pending组可以存在；导出只能回放到已知frontier。自然结束的文件不能带未完成组；缺尾行/哈希损坏不冒充完整局。

## 10. 验收要求与空间预算

以下是实现必须验证的内容，实际完成范围见独立验收说明：

1. 开序章与不开序章：初始状态、12选7、正式开局、每轮末检查点位置正确，序章无中途全量。
2. 建陆+目标+结果只一条；兵贵攻击+目标+消灭只一条；英国实际保持冷静另列，未发动响应无条目。
3. 对所有已完成动作，省略可选响应等价于默认跳过；必选数据缺失报错，未完成组在frontier停止。
4. 多次同名攻击/同牌响应、嵌套响应定位准确，不串错国家和目标。
5. 威廉皇帝学会、资源重整等每次洗牌保留完整洗后顺序，多次回放一致。
6. 每个可点击条目前后，推导出的单位、分数、卡区/牌序、持续状态、知识与实际录制时一致。
7. 从start顺序回放与从最近检查点回放一致；回放不写实时存档、不发网络命令。
8. 回退含动作内部、跨检查点、pending导出均准确删除废弃后缀和随机结果；版本不符明确拒绝。
9. 有适配器的训练课程用真实样例联调；未支持变体明确提示，不声称通用兼容。
10. 统计JSON未压缩/压缩大小，并按初始状态、检查点、动作、洗牌/随机分类。完整状态数量必须符合本规范，不得存在隐蔽的before/after快照或累计历史嵌套。用“序章结束、第一轮未完成”案例对比旧版约300MB文件，报告实测降幅；不预先保证任意对局固定大小。

目标是让文件体积随完整动作数和轮数线性增长，而不是随着内部状态复制迅速膨胀。外层压缩可以使用，但不能仅把旧全量格式压缩后称为增量实现。
