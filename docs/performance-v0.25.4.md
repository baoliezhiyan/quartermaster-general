# v0.25.4 多人可靠性与性能检测

日期：2026-09-13。运行环境：本机 Windows、Node 24、Edge。继续支持本机服务器和 Cloudflare 隧道。

## 本轮已完成

1. 起手留牌、地图目标、空军调度步骤与费用选择不再因无关全局更新清空；短暂断线不会卸载整个游戏界面。
2. 服务端签发个人操作标识，允许同一有效问题跨无关版本更新提交；仍校验权限、选项和费用。新建、读档、回退或 GM 修改局面使旧操作失效。未开放任意旧指令强行重放。
3. 提交期间防重复点击，等待服务器确认对应快照。丢失回复、超时重试和自动核对沿用同一操作编号；迟到快照不能覆盖新局面。
4. 检测中复现并修复网络分块解码中文导致乱码的问题：改为收齐字节后统一 UTF-8 解码。此项属于传输正确性修复，存储格式没有改变。
5. 中国卡边 #F04444，苏联卡边 #960000。

已通过 322 项自动测试（34 个测试文件）、类型检查、构建。七页面浏览器验证覆盖：未确认的起手选择保留、并发确认、重连、地图目标保留、空军拒绝及目的地/费用草稿保留、服务器执行后故意丢失回复再重试。浏览器无页面异常。

## 检测方法与范围

服务端运行六个国家加 GM 的七个接收端，完整推进 20 轮、900 次操作。真实执行 JSON 序列化、临时文件写入、fsync 和重命名；每个接收端生成并序列化自己的权限视图。操作以正常推进、弃牌、摸牌和跳过可选响应为主，没有密集战斗连锁，不代表所有实战上限。记录只收集阶段耗时和字节数，不收集测试参与者的秘密信息。

另用实际 Edge 界面的 GM 与德国页面，在第 1、10、20 轮存档各执行 8 次请求，测量 HTTP 往返、消息字节数及前台 GM 从收到消息到两次动画帧回调的延迟。后者包含浏览器调度和绘制机会，不等同于精确 React 渲染时间。后台标签页的动画帧会受节流影响，未用于性能结论。

这些都是本机测试，没有测量真实 Cloudflare 公网延迟、家中上行带宽或同学电脑的性能；测试时的系统负载和垃圾回收也会影响结果。性能诊断默认关闭，未实施增量同步、历史精简、异步延后落盘或存储重构。

## 服务端结果

每组取三个轮次的 135 次请求：前期第 1—3 轮、中期第 9—11 轮、后期第 18—20 轮。单位毫秒，以下为均值；包含项不能重复相加。

| 项目 | 前期 | 中期 | 后期 |
|---|---:|---:|---:|
| 单次请求总处理时间 | 31.1 | 133.1 | 296.2 |
| 规则引擎单次 transition | 1.0 | 3.0 | 6.0 |
| 复制整个会话 | 8.4 | 46.9 | 116.1 |
| 保存合计（含编码和落盘） | 9.8 | 44.2 | 101.3 |
| 其中 JSON 编码 | 3.6 | 18.3 | 43.2 |
| 其中写文件、fsync、重命名 | 5.7 | 22.9 | 50.7 |
| 七用户广播合计 | 7.5 | 23.4 | 42.9 |
| 请求总处理时间 P95 | 47.6 | 164.0 | 343.3 |
| 每次完整存档大小（十进制 MB） | 1.10 | 5.80 | 13.69 |

后期复制会话与保存合计约 217 ms，占平均请求时间约 73%；单次引擎 transition 约 6 ms。因此首先应处理反复复制历史和重写整份存档，而不是先归因于地图或 Cloudflare。这里的引擎计时不包含请求校验、视图生成等外围工作。

第 20 轮约 12.3 MB 的存档已在浏览器成功导入并继续操作。GM 全知视图增长尤其明显；如果 GM 也通过公网链接访问，隧道需要传输这些数据。当前抽样中前台绘制等待的增长远小于服务端请求增长，暂不建议先重写地图。

## 下一轮建议（本轮未实施）

优先一：保持完整回放和回退能力，将“每步克隆整份会话”改为只复制本步变化的状态与必要容器，避免重复复制不可变历史；用一致性测试确认旧存档、回退与回放结果不变。

优先二：设计追加式操作日志加定期完整检查点，减少每步重写十余 MB 文件。先确保每个已确认操作有可恢复的持久化记录，再确认成功；验证异常退出、断电模拟、写入失败、重启恢复和手动导出 JSON。不能通过不保存操作来换取速度。

优先三：将座位/在线状态与游戏状态分别同步；按权限直接构造个人视图，减少先复制全部秘密状态和历史再删除的开销。进一步评估增量消息、日志追加及断线全量补齐。GM 调试详细数据改为需要时读取，仍须维护实时可操作信息。

优先四：根据上述改动后的新测量，再决定是否对长日志、卡牌列表和地图进行局部渲染优化。每步采用相同 20 轮基准复测，并补充密集响应/战斗场景，最后再由六人通过真实 Cloudflare 隧道验收。
