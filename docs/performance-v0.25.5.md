# v0.25.5 多人性能优化验证

日期：2026-09-13。对比基线：v0.25.4。本轮面向“本机开服 + Cloudflare 隧道”的使用方式，未改变端口、入座权限或卡牌规则。

## 结论

相同的 20 轮、900 次实际规则操作中，后期服务端平均请求耗时由 296.17 ms 降至 53.47 ms，减少约 **82%**；后期 P95 由 343.30 ms 降至 65.89 ms。每次广播、每个接收者平均发送量由约 147.08 kB 降至 14.21 kB，减少约 **90%**。

这不是公网测速。隧道连接质量、往返延迟和客户端机器性能仍会影响体感。

## 实现

1. 已提交状态保持不可变；复制会话时仅复制需要修改的数组容器，复用历史状态。撤销、恢复、回放仍保留原有记录。
2. 自动保存采用完整检查点加增量日志。每次操作先完整追加日志、fsync 成功后才确认；默认每 50 次保存或日志达到 16 MiB 时整理检查点。序号、基础版本和 SHA-256 用于校验恢复顺序和内容。
3. WebSocket 在同一连接、相同可见范围下发送增量；进入房间、切换视角或对局等情况发送完整视图。增量序号不连续时请求完整快照。同步基于已经过滤过的视图，普通玩家不会收到 GM 的隐藏内容。
4. 上下线、入座等房间变化复用现有视图；普通视图在复制之前去掉引擎回滚树和不公开的结算历史。删除了一次重复的规则预检状态复制。

初次试跑发现 2 MiB 日志阈值会在后期频繁整理检查点，因此正式配置调整为 16 MiB；以下数据均为调整后的完整复测。

## 相同长局基准

六国加 GM，共七个接收者；同一个种子、相同操作驱动。覆盖保留起手、阶段推进、弃牌、抽牌及跳过可选响应，直到对局结束。不是复杂连锁卡牌压力测试。实测包含真实 JSON 编码、日志写盘、fsync 和检查点替换；按早期 1–3 轮、中期 9–11 轮、后期 18–20 轮分组，每组 135 次操作。

平均毫秒（v0.25.4 → v0.25.5）：

| 项目 | 早期 | 中期 | 后期 |
| --- | ---: | ---: | ---: |
| 整项操作 | 31.13 → 19.26 | 133.13 → 29.94 | 296.17 → 53.47 |
| 复制会话历史 | 8.43 → 0.00 | 46.95 → 0.00 | 116.10 → 0.00 |
| 自动保存（含检查点整理） | 9.75 → 9.30 | 44.20 → 11.27 | 101.33 → 23.09 |
| 规则结算 | 0.98 → 1.06 | 2.96 → 3.02 | 6.01 → 5.57 |
| 过滤视图与广播 | 7.51 → 7.55 | 23.43 → 12.11 | 42.87 → 18.26 |

后期单次日志平均约 602 kB，而旧版每次完整存档平均约 13.69 MB。后期 135 次操作中整理了 5 次检查点，整理平均耗时约 175 ms，这些耗时已包含在表内。整理当次仍可能有短暂等待，优化并不意味着所有请求都低于 66 ms。

长局结束后重新从磁盘读取检查点及日志，得到的完整会话与提交状态一致，并通过确定性回放校验。

## 可靠性与交互验证

- 七页面回归通过：他国确认起手不清空本国选择、六国同时提交、重连保留草稿、地图目标保留、空军跳过及来源/目标/费用选择保留、HTTP 回复丢失后以同一编号重试。无浏览器脚本错误。
- 增量连续应用及丢失后全量补同步、换座全量同步、隐藏信息过滤通过。
- 日志正常恢复、未完成尾记录、完整记录损坏、写入失败回滚、检查点整理失败、检查点写好但日志未清理等测试通过。故障为注入测试，未模拟真实硬件断电。
- 实际服务器停止再启动：保持空房、原身份返回、GM 恢复局面、回放验证和新建局清空旧日志通过。按已有读档规则，恢复会推进修订号并建立新的行动起点。
- v0.24.0 实际旧存档导入及回放校验通过。
- 类型检查、客户端与服务器构建通过；36 个测试文件、334 项自动测试全部通过。

## 使用与备份

解压 v0.25.5 后沿用原 Cloudflare 启动方式，关闭旧游戏服务后再启动新服务，参与者刷新页面。

游戏内手动导出的存档仍是一个 JSON，原有读档方式不变。新版服务器自动存档是 data/current-game.json 与 data/current-game.journal 两个配套文件：前者是内部检查点，后者记录之后的操作，不能只复制前者作为最新备份。搬迁整个服务时先停服再复制 data；其中 identities.json 包含身份凭证，请勿公开分享。旧单文件自动存档可自动迁移。新建对局会替换旧检查点并清空旧日志，保留身份以及手动导出的备份。
