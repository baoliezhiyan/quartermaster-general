# v1.6.11回放核对与迁移说明

2026-09-30。本次为发布包静态代码核对，未启动游戏、未运行测试，未取得可确认由1.6.11导出的实际故障对局。因此不能宣称已复现用户故障，或证明旧记录覆盖全部情况。

核对对象：`releases/战场军需官-v1.6.11/version/package.json`与`dist-server/Room.mjs`内的replay、LocalGameController、saveFormat、shuffle实现。当前src仍保留部分旧实现，但结论以该发布包为依据。

## 可以沿用的思路

旧版RecoveryRecord保存initial与steps；step是成功command或restore。重演直接调用transition，随机洗牌由state.randomState推进。这条“初始状态+操作重演”的路线是合理基础，不需要逐步全量快照才能还原游戏。

旧版保存目标/费用等实际命令，而不只是“某国打出了某牌”的文本，因此普通操作的信息基础比公开对局文字充分。相同引擎、完整命令和完整随机状态具备确定性重演的基础；仍需真实样例核验。

## 已确认的实现行为及迁移要求

| 旧实现行为 | 影响与新要求 |
| --- | --- |
| 1.6.11包的exportReplay硬编码appVersion为1.6.1；prepareReplay只检查rulesVersion=1.4.0，不校验appVersion | 不能据此确保用了同一结算引擎；新格式写真实构建版本及引擎/规则指纹并严格检查 |
| replayStateAt只寻找此前restore，没有按正常轮末利用存档检查点 | 未回退的长局每次跳转都可能从开局推导；新格式每个正式轮末存检查点 |
| prepareReplay先完整推导一遍，导入随后showReplay又推导到末尾 | 导入重复计算；新实现复用一次校验结果或按需推进，不重复重演整局 |
| showReplay创建fresh session并调用正常commit；commit会写SessionStore、更新session/state | 回放展示耦合实盘保存；改为独立只读回放会话，不经正常游戏写盘 |
| 每个command产生候选条目，RESOLVE_ENGINE_CHOICE空选择可显示“结束本次响应或选择” | 与新要求的完整动作和省略跳过不符；动作聚合后再显示 |
| 记录SET_VIEW、ACK等以及命令expectedRevision，重演逐条transition | 不能删掉这些命令后继续原样重演；新适配器负责视角/修订上下文及必要自动确认，规则答案才持久化 |
| undo/读档追加restore快照，旧分支仍留在steps | 新版改为截断废弃后缀；外部不相关存档开启新记录 |
| shuffle靠randomState重算；可见描述只写“牌库顺序已调整” | 不代表旧版必然随机错误，但不满足新裁定；新格式每次洗牌保存完整洗后实例顺序并正确推进随机流 |

另外，outputs中的lazy-replay.json声明0.25.6，配套诊断也属于早期版本，不能当作1.6.11的故障样例或验收证据。

## 对“记录没有问题，只是推导有问题”的判断

方向上可认同旧版记录拥有重要基础，但现有证据不支持把所有问题都归到推导函数。版本校验、会话隔离、跳转效率和条目组织已有明确不足；旧命令记录本身也不满足这次新的精简粒度、回退截断及洗牌实录要求。

新实现优先复用transition及卡牌结算，不另写一套卡效。增加动作录制聚合器与回放适配器：把实际选择绑定到正确时点，省略的可选响应自动跳过，检查点恢复后继续推进。不能从中文摘要猜命令，不能把所有响应永久禁用（那会连明确记录的响应一起禁用）。

后续用同一次实际对局在录制时采集的临时状态哈希对比回放；哈希差异定位到第一个动作。调试数据可临时保存，正式回放不把这些全量状态带进去。
