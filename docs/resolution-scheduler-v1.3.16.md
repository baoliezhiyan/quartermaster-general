# v1.3.16 结算调度约定

本轮把已发生的事件、等待处理的触发机会、卡牌自身完成与整条连携收尾分开。正式规则的新结算使用 `schedulerVersion: 1`；正在进行的旧结算缺省保留旧窗口分支行为，不在读档中途强行改写栈。基础调试场景继续用于验证旧模型。

## 生命周期

每个子效果保留所属 frame、序号、来源事件、效果快照与结果：declared、succeeded、cancelled、invalid。started 表示进入实际执行，ended 表示子效果及其执行所需内部步骤完成。初始不合法的效果记录 invalid，不能产生成功触发。

实际流程为 Validate → Apply（之前允许响应）→ After（登记子效果结束）→ AfterImmediate（立即响应完成）→ 本牌自身完成检查 → 后续响应窗口 → Resume。最后一个实际效果完成时记录 CARD_OWN_EFFECTS_COMPLETE；尾部 CARD_PLAYED 等簿记信号不把它拖到后续连携结束。状态完成通知单独绑定 completedFrameId，防止密码错误指向后续牌。

FINISH_CARD_RESOLUTION 仍表示该 frame 及其后续窗口收尾，并负责最终归堆。卡牌提前回手后已不在 resolving，收尾不得再次移动它。取消安装也不回滚已经发生的其他事件。

## 窗口与候选

- 每个窗口绑定 originEventId。构造、战斗成功的历史事实不因部队后来被移除而消失。
- 建设后立即消灭等 placementPriority 响应在 immediate 通道处理；普通后续动作在 followup 通道处理。
- 每次重返窗口重新生成事件绑定的规则，检查当前费用、目标、兵模与补给。曾经生成、后来不再匹配条件的动态规则不得沿用。
- opportunities 区分 available、temporarily-illegal、declined、fired；临时不合法不记作玩家放弃。
- 放弃限定到具体窗口；批量响应明确限定到同一 batch。不能传染到另一场攻击或另一项建设。
- 自 v1.7.2 起：选择祖先窗口发动同级效果时，关闭离开的更深子窗口；保留祖先仍有效的机会。已完成的效果和帧收尾不撤销。详见 rules-v1.7.2.md。
- 窗口耗尽才关闭；关闭的窗口不在以后回合重新打开。每回合次数仍按牌实例与 scopeId 约束。

## 闪电战合并入口

仅合并同一闪电战的多个仍开放触发机会。界面一个入口，mergedTriggers 保留所有 windowId/ruleId。点开后按当前 boardOptions 合并合法地区，triggerTargets 将地区对应回真实触发来源；同一地区多来源按稳定顺序选一项。

确认地区时服务器再次核验来源和合法目标，随后走正常费用、发动、建设流程。没有合并卡牌效果、费用或次数。目标选择尚未确认时不消耗牌库费用。不适用这种特例的牌仍独立处理。

## 纯计分状态批量响应

仅在 PHASE:SCORE、至少两张必发持续状态、全部效果都是无费用且无选择的 score 时创建批次。可选计分增强、建设、弃牌等不纳入。

1. 建立各张状态独立的 frame 与 CARD_EFFECT 事件。
2. before 阶段把英国可用的保持冷静目标放进一个列表。选择一个目标仍只发动一张响应、支付一次原费用；全部跳过只放弃这次批量询问。
3. 按稳定次序执行未被取消的各张状态；实际执行时重新计算分值。
4. after 阶段为已执行状态分别产生完成事件，合并显示合法密码目标。被取消的牌不列作已执行目标，密码弃牌不撤销已得分。
5. finish 阶段分别归堆，之后继续原计分窗口。

批次不是一个合成卡牌：原实例、触发来源、取消状态、日志与归堆均独立。未来如出现其他能改变批次成员条件的得分联动，必须审查批次资格，不能直接扩大本特例。

## 存档与多人

scoreBatches、执行游标、响应窗口、合并目标映射都是可序列化状态。存档校验检查批次与 frame、window、rule 引用。非 GM 网络投影删除内部批次与窗口，仅向实际操作者发送当前合法选项；不向对手发送暗置响应。

## v1.5.6 战后被攻击方优先

陆战、海战和夺取制空权的生效后窗口，先处理本次被攻击国家的可用战后响应(含必发效果)，再询问攻击方连携。被攻击国家由战斗选项快照确认，不能依赖战后仍然存在的兵模。防守响应期间仅展示当前窗口的机会；子效果完成后重新检查原战斗窗口的合法效果与目标。跳过仅关闭当前事件中该玩家的机会，不影响下一次战斗，也不因地图变化重置已跳过标记。卡牌生效前后响应及建设后优先处理机制继续独立工作。
