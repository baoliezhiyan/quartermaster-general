# 第十步：本地存档、回退与诊断

## 用户裁定的存档层级

| 类型 | 保存时点 | 保留方式 |
| --- | --- | --- |
| 大存档 | 完成起手后的第 1 轮，以及此后每轮德国行动开始 | 每轮一个，最多 20 轮；不生成第 0 轮轮存档 |
| 小存档 | 每次切换到一个国家开始行动 | 每国一个，最多六个；新一轮轮到该国才替换它上一轮的槽位 |
| 当前进度 | 每个成功提交的操作后 | 自动覆盖本局最新状态，用于刷新/关闭后继续 |

第 0 轮的起手进度仍会作为当前进度自动保存，刷新不会丢失，但不列入大/小存档列表。起点保存的是回合开始结算已建立、等待玩家选择的完整局面。尚未轮到的国家没有初始小存档；下一轮尚未轮到的国家继续保留上一轮的小存档。

在地图下沿展开「存档、读档与备份」，可直接读取任何大存档或小存档。读取不消费槽位，也不删除其他已有存档。此后再次到达相同轮/国的起点时更新对应槽位。

## 回退

- 点击「回退一步」撤销最近一次成功提交的游戏操作，包括打牌、确认目标、费用/响应选择、阶段推进和场景应用。
- 最远退到当前行动国本次行动开始。进入下一国或下一轮德国时重置回退记录；不能借回退回到上一国。
- 查看其他国家不计入回退步骤。未提交的地图点选属于界面状态，使用再次点击或取消选择，不生成回退记录。
- 不提供重做/快进。读取大、小存档从该起点重新建立回退记录；恢复当前进度或导入完整存档保留其中的回退记录。
- 恢复局面后使用新的单调递增修订号，清除旧界面选择，过期命令仍被核心拒绝。

## 持久保存与文件

IndexedDB 数据库 `quartermaster-local` 按 gameId 保存各局完整会话，另外记录最近使用的对局。每次写入使用原子事务。新建对局不会删除原局，可从「查看其他本地对局」读取。

保持同一浏览器和同一地址（通常 http://127.0.0.1:5173/）即可自动恢复。换浏览器、端口或电脑请使用 JSON 导出/导入；浏览器清理站点数据也会清除 IndexedDB，因此建议留 JSON 备份。

存档包括随机状态、牌堆顺序、全部牌区、分数、兵模、持续修正、待处理结算及选择、回退快照、大/小存档和回放基准/命令。规则版本当前只接受 1.2.2、存档格式版本 1。不兼容、缺牌、重复实例、不完整结算和回放不匹配会明确拒绝，不替换当前对局。JSON 导入上限 64 MB。

保存失败会显示持久保存错误，但内存对局仍可继续并导出备份。多个窗口同时编辑同一局时检测写入版本冲突，避免旧窗口覆盖新存档；重新读取本地对局可恢复到已保存版本。

## 回放和诊断

「校验当前回放」从本局创建/最近读档、回退或场景编辑后的基准状态重放已接受的命令，与当前完整状态比较；仅校验，不改变局面、不构成重做。

「导出错误诊断包」包含完整存档、应用版本、最近失败命令和填写的问题/预期结果。原始源资料和开发方案文档未改，以上是本次实施补充说明。

## 验证

控制器自动测试覆盖两轮六国槽位轮换、读取各类存档、回退边界、视角切换不计回退、过期修订拒绝、完整结算恢复、建设确认后回退改选、结构/版本损坏拒绝、存储失败提示、独立对局保留、场景应用撤销和确定性回放。

浏览器实测完成六国起手自动建立第 1 轮存档、刷新恢复待选建设目标、落子后回退、读取轮起点后禁用越界回退。
