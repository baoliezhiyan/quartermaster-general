# 第五步：结算器纵向切片

依据开发方案 v1.2.1 第 12 节阶段 5，以及第 5 节嵌套结算规则实现。提供六个明确标为示例的交互裁决；不将示例牌伪装成正式卡池。

## 完成内容

- 序列化的结算帧、效果游标、事件祖先信息、帧/窗口任务栈和 ChoiceRequest。一次处理一个效果，完整完成子结算后才推进父效果游标。
- Validate → Declare → Before → Apply → After → 子结算 → Resume。响应结束后再次检查当前条件；效果取消或条件失效时，不执行 Apply，也不产生成功后的 After。
- 可选窗口保留初始候选快照。每次返回重新检查剩余候选，只删不补；同时展示当前和祖先窗口的合法候选。选择祖先候选会关闭较深窗口，但不删除已开始卡牌的剩余效果；结束时点仅关闭当前最深窗口。
- 多个同事件必发效果必须由有权玩家提交完整顺序。错误、遗漏、重复、外来项或过期选择均拒绝，不替玩家按照注册顺序排序。
- 响应来自已暗置区，增强来自符合条件且足以支付费用的手牌；支持明确标记的暗置增强例外。归属资格以牌堆席位判断，不拿法国/中国兵模归属替代牌堆归属。
- 默认忽略他国可选插入；被要求强制弃牌的对手仍必须选择。选择完成后恢复暂停的结算，全部完成后返回原操作者。结算期间禁止推进普通阶段、打基本牌或操作第四步试验面板。
- 增强费用完整支付后才正式触发。正式打出/触发的实例进入 resolving，所有子结算结束后统一收尾；支持弃牌、持续区、手牌、牌库并洗牌、暗置区、移出游戏等最终去向，不重复落入默认弃牌堆。
- 事件与来源实例的重复触发记录、来源祖先链及按轮次/行动席位划分的每回合次数计数。支持暂停状态 JSON 往返后继续得到同一结果。

## 六个试玩裁决

完成六国起手后，在「第五步 · 结算器纵向切片」选择示例。试验会改变当前局面的牌堆或分数，不推进阶段。再次开始示例只清理此前示例牌，不替换普通卡牌。

| 示例 | 应有结果 |
| --- | --- |
| 子结算优先 | A → B1 → C1 → C2 → B2 |
| 祖先窗口 | 选 B、D、C：A → B1 → D → B2 → C；选 B 后直接 C：A → B1 → C → B2，D 错过时点 |
| 生效前取消 | 接受响应后不扣 3 分，也不触发成功后奖励；放弃响应则先扣 3 再加 1 |
| 必发排序 | 选择 C、B：A → C → B1 → D → B2；不允许跳过或遗漏必发项 |
| 对手强制选择 | 对手摸牌后选择弃两张，完成后才执行父帧下一项并返回原行动席位 |
| 来源、费用与快照 | 仅出现已暗置响应、可支付的手牌增强和本席位连携；手牌响应、他国可选响应、后来才满足条件的旧事件候选不会出现 |

面板显示实际执行顺序，并可展开查看帧状态、尚未关闭的窗口和结算中卡牌。对局日志区保留逐项宣告、执行、窗口建立及卡牌收尾记录。

## 验证

89 项自动测试、类型检查和生产构建通过。包括原有 65 项回归，以及深度优先、窗口保留/截断/仅关闭最深层、必发完整排序、取消前后分支、响应后条件失效、费用支付、来源例外、六种最终去向、同事件与祖先防重复、每回合次数、强制他国选择、序列化恢复和错误命令原子拒绝。

页面实际验证了完整六国起手、嵌套顺序、祖先 C 截断 D、C 优先的必发排序、对手强制弃牌后恢复，以及响应来源和增强付款。验收中修复了两处同级面板使用相同 React key 导致旧手牌面板残留的问题。

## 本步边界与下一步

本步为独立的结算器纵向切片，复用第四步真实牌堆操作，并接入统一命令入口与回合操作门控。已有基本战斗、建设与阶段流程尚未全面改走新效果栈；示例事件标签用于验证时序。代表卡的具体条件、战斗/空军事件适配、阶段触发（包括资源重整和回合开始效果共用窗口）在第六步按真实牌面接入，随后第七步录入完整卡池。

开发规则原件和地图保持原版本。本步不实现存档、回放 UI 或正式卡池。第五步完成，停止在本步供验收；下一步为「代表卡牌集」。
