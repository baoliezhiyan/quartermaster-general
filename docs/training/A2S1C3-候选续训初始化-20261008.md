```bat
"PPO训练\启动A2S1C3候选续训.cmd" show
```

启动器使用本机已验证的 `D:\Python\python.exe`、Codex 本机 Node 路径及此训练工作树已有的 `node_modules`；不复制运行时、不自动安装依赖、不打开全屏。进度位于 `.state/A2S1C3/latest.pt` 与 `training-report.json`，运行计划在 `.state/A2S1C3/plan.json`。每次完整更新保存可恢复模型和优化器。计划中断后，继续会从最后一个完整更新重采未完成的 40 局；不会把半批次当完成，也不会额外增加轮数。计划与检查点校验实验、候选、课程池、训练种子、规则、编码、奖励和网络身份，错误时拒绝启动。

## 连携统计口径

`training-report.json` 每次更新附 `comboDetailSummary`；每轮 `轮次统计摘要.json` 有十次更新汇总。所有指标按正常开局、课程准备层、课程兑现层分别统计。G1 闪电战 `special_136`、U4 先进造船厂 `special_84`、J1 全面侵华 `special_199` 的选择与实际安装/暗置分开；课程接管前已有牌另列，不能算模型自行准备。触发机会只统计合法候选出现的独立决策窗口，重复观察不重复记；发动与主动空跳过分开，分母为 0 时发动率为 `null`（无机会）。

有效使用要求结构化事件的父子/祖先关联、真实新增单位等结算证据；普通跨回合攻击后建设不算。通用有效用法与模板目标分别统计：G1 的实际攻后建设与乌克兰目标、U4 的实际追加建海与第二轮北海目标、J1 的中国东部攻击后响应建设及占领。受反制、付款和未兑现原因尽量按来源记录；无法从轻量遥测确认的费用或原因单列为未归属/未确定，不能据“没看到成功”猜成模型主动放弃。原九模板指定链统计继续保留。遥测只读，不进入模型观察或训练奖励。

## 第 1 轮回放导出修复

用户随后完成更新 10、累计 400 局；检查点和训练报告已保存，轮末回放导出却失败。第一份正常对局在闪电战建设中东时，德国的旧陆军已作为回收费用在较早命令移除，建设事件仍携带这个历史回收 ID。转换器误把历史 ID 当成建设当下还要移除的单位，因而拒绝合法建设。现把实际回收记作独立 `remove/cost` 场面操作；只有已核实先前回收事件的 ID 才允许从后续建设操作中去掉重复的回收字段。第二份概率抽样对局中，日本响应直接消灭英国海军并在同一命令结束结算；终态已经进入新阶段，旧转换器拿不到中途的移除事件。现要求该决策的结构化效果明确指向被移除单位，才能补记直接移除；无证据的移除仍不得冒充断补。
