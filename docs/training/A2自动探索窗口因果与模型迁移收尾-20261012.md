# A2 自动探索窗口因果与模型迁移收尾（2026-10-12）

基线 `f896e85`；训练工作线。本轮只修路线重放元数据和历史开局门控迁移。没有修改正式玩法、奖励、现有课程池或 61 张待核实牌的语义清单；没有 PPO 更新、自然探索或学习效果试验。

## 被取消窗口的因果身份

`scripts/ppo_route_causality.mjs` 在训练服务器读正式结算器的帧、事件和窗口，按「本局结算序号 → 父事件 → 卡牌/行动来源 → 效果位置及同源实例 → 窗口时点及实例」生成哈希令牌。目标地区、发起国家、守军国家和行动类型参与事件令牌；原始 `frameId`、`eventId`、`windowId` 仅在当前状态中用作关联键，不直接跨分支比较。关闭、取消和失效状态来自结算窗口及事件；没有呈现给模型的窗口也在引擎窗口历史中。结算序号取正式状态的 `balanceResolutionSerial`，快照恢复和重新启动后不依赖 JS 对象地址或模型看见窗口的次数。

训练服务器仅在离策略 `comboTelemetry` 路径返回 `routeCausality`，并将其保存在训练快照的独立字段中；`PpoObservation` 和神经网络输入不含该字段。`ppo_auto_route_match.py` 对引擎选择节点要求来源令牌一致。原窗口被取消而后续出现同上下文窗口时，路线中断；旧路径没有因果元数据时标为 `unresolved_window_causality`，不猜测成功。敌方合法响应插入而原事件存续时，后续仍可匹配。现有动作签名的守军、攻击来源、目标、费用和分支检查继续执行。

真实引擎测试构造一张牌的两个同名效果：英国在首个生效前窗口取消它，德国没有见到首个生效后选择，随后第二个同型效果产生窗口。首、次窗口令牌不同；插入不取消的合法英国响应时，德国首窗口令牌保持相同。序列化恢复后令牌一致。训练客户端另验证跨 Node 重启恢复、配对随机分叉、观察字段隔离。仍有边界：若引擎完全不保留某个瞬时窗口记录，或未来新增未列入语义令牌的行动事实，执行器只能标记未解决，不能推断等价。
