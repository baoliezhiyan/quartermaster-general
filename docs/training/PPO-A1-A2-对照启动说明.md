# PPO A1/A2 对照启动说明（准备阶段）

双击仓库根目录 `PPO训练/启动PPO训练.cmd`，输入本次**每组新增轮数 N**。A1 与 A2 均为竞技场资源模式 A（所有剩余资源可用），都用 `ppo-observation-v5` 的重复建设编码及 `repeated-basic-build-v1` 的 -0.01 惩罚。A1 熵系数 0.01，A2 仅将其改为 0.02；网络、价值损失权重、PPO 轮数/小批次、课程和训练种子一致。两组顺序运行，每轮 10 次更新、每次 40 局，共新增 `2 × N × 400` 局；默认 8 环境，使用原有有界磁盘轨迹。旧 A/B 成果和归档不参与新训练。本阶段只交付入口，**未启动正式 N 轮训练**。

入口将目标轮数和配置保存到 `.state/comparison-plan.json`。例如当前两组都是 0 轮，输入 `2` 会先使 A1 达到 2 轮，再使 A2 达到 2 轮。计划全部完成后再输入 `1`，两组才各新增 1 轮。中断后，双击入口输入 `C` 或运行 `启动PPO训练.cmd --continue-plan`，继续未完成目标；新建计划不能覆盖未完成计划。若 A1 完成、A2 中断，恢复会验证 A1 的成果、报告和检查点，跳过其已完成轮次，只继续 A2。每组内部按已完成更新恢复；未完成的 40 局批次从上一个完整更新边界重跑。检查点实验身份、资源模式、熵系数、初始化权重哈希、奖励、编码、构建和种子不符时拒绝。

只看计划、完全不写入训练文件：`启动PPO训练.cmd --rounds 1 --dry-run`；已有未完成计划则用 `启动PPO训练.cmd --continue-plan --dry-run`。计划文件和共用 `.state/comparison-initial.pt` 属于本地训练状态，不提交 Git。新实验从同一份按训练种子生成的随机权重加载，A1/A2 各自新建优化器和后续检查点；模型张量 SHA256 记录在计划、检查点和报告。逐局环境种子与策略采样随机流的推导不混入 A1/A2 名称；同一更新号使用同一任务种子。每轮展示局和参考评估种子在两组间相同，且不参与训练或消耗训练进程的随机流。

| 目录/文件 | 用途 |
| --- | --- |
| `PPO训练/A1/第001轮/`、`A2/第001轮/` | 各轮模型 `模型.pt` 和可导入 `AI训练记录.jsonl` |
| `PPO训练/.state/A1/`、`.state/A2/` | 各组完整更新检查点与 `training-report.json` |
| `PPO训练/.trajectory-temp/A1/`、`.trajectory-temp/A2/` | 分开的临时轨迹目录；每次完整更新保存报告后清理 |
| `PPO训练/归档/A-20261002-截至第004轮/` | 旧 A 四轮及续训状态，只读留存 |

每次更新报告记录重复基本建设、惩罚次数和国家分布、惩罚总额；另外统计**决策时存在结构上可惩罚重复建设候选**的次数及其中实际选择该候选的比例。这个机会分母在出牌前检查候选和已安装效果，不依赖模型最后选了什么；真实惩罚仍以完整行动结束后的严格判定为准。报告还记录推理策略熵、按候选数归一化熵、最高动作概率和单候选决策数；既有采集/优化耗时、内存/显存峰值、临时轨迹读写与清理保留。每轮 `roundReviews` 记录苏联乌克兰、日本中国东部固定局面偏好，并在固定种子 `20261021`、`20261022` 上分别由学习者控制轴心和同盟、对阵冻结的**未训练初始策略**，共 4 局。这个对手只提供同条件的诊断参照，实力很弱，不能把对它的胜率当成整体棋力。每轮可导入的自我对打记录是另外一局，采用模型贪心动作。

对照分析不以总训练奖励或自身对打阵营胜率单独下结论；应同时比较重复建设机会选择率、资源利用、动作分布、对固定弱参考的变化趋势、局长、模型偏好及记录内容。当前尚无可靠强固定对手，四局参考预算也不足以给出精确棋力估计。旧 v4 权重不直接续训新实验。两组训练源、构建指纹、课程、编码、奖励、预算及初始化相同；熵系数和实验身份是刻意不同的配置字段。
