# PPO 轮次训练启动说明

双击仓库中的 `scripts/启动PPO训练.cmd`，它先构建与当前源码指纹匹配的客户端和回放校验器，再询问目标总轮数 `x`。每轮为 10 次更新、每次更新 40 局完整训练对局。程序默认使用 **10 个持久环境和一份 GPU 模型**，先连续完成 A 课程的 `x` 轮，再完成 B 课程的 `x` 轮。输入 1 会分别训练 A、B 各 400 局；固定种子的评估局及每轮抽样记录局另计，不进入训练样本。运行时不会打开全屏窗口。本入口适用于客户端 v1.7.6；旧规则检查点不会自动迁移。

相同命令的非交互形式：

```powershell
python -m scripts.ppo_rounds --rounds 1
```

执行前可仅检查计划，不开始训练：

```powershell
python -m scripts.ppo_rounds --rounds 1 --dry-run
```

结果存于 `outputs/ppo-training-v1.7.6/A/第001轮/` 和 `outputs/ppo-training-v1.7.6/B/第001轮/`，后续轮次依次编号。旧版 `outputs/ppo-training/` 保留；两套规则构建不混用。每个轮次目录只有两个供查看的文件：

- `模型.pt`：该轮结束时的策略/价值网络权重及模型、课程、构建元数据；不含优化器，因此不能单靠它恢复训练。
- `AI训练记录.jsonl`：在固定的 20 个评估种子中随机选一个，再随机选学习者阵营，使用该轮模型对战同一冻结规则对手。文件采用 `quartermaster-match-log / formatVersion=3`、`mode=resource_pool` 和 `quartermaster-training-scene/1.0.0`；开头的 `training.configuration.recordKind` 标注“AI训练记录”。每次引擎命令对应一条可展开的 `training_action`，包含实际场面操作、卡牌移动及场面摘要。完整卡表、自然终局结果和模型/种子元数据随文件保存。导出时会运行协议解析和逐步场面重演；任一步不匹配则本轮结果不会发布。此文件可由支持训练回放适配器且场面规则指纹一致的游戏版本导入；它不是正式对局的出牌命令回放。

训练场不模拟 7 张真实手牌，因此回放中六国 `hand` 始终为空。尚未消耗的卡牌显示在 `drawPile`，已消耗的显示在 `discardPile`；出牌、费用和恢复等变化写成逐卡牌区移动。A 课程的 `resourcePool` 始终为空；B 课程在本国回合开始写入当轮开放卡牌，消耗后删除，并在下一次本国回合刷新。所有牌区都只是独立展示，不参与场面合法性重算。单独校验文件可运行：

```powershell
node scripts/validate-match-log.mjs "outputs/ppo-training-v1.7.6/A/第001轮/AI训练记录.jsonl" --replay
```

`--replay` 会逐步重演场面与牌区；不带此选项只能验证格式与文件完整性。若导出失败，不会建立正式轮次目录；报错标出未能还原的动作。协议见 `docs/training-replay-output-v1.md`。

每轮训练后仍按既定评估协议，对固定 20 种子分别由学习者扮演轴心和同盟，共 40 局；评估指标放在内部报告中，与抽样可读日志分开。完整检查点和评估报告位于 `outputs/ppo-training-v1.7.6/.state/A/`、`.state/B/`，不放进轮次目录，也不应发布到 Git。检查点包含模型、优化器、随机状态、累计训练量和规则指纹。

再次输入较大的目标总轮数会跳过已有完整轮次，从最新完整更新检查点继续；输入原轮数不会重复训练。若进程在 40 局批次中途停止，只能从上一个完整更新边界重跑该批的相同任务；不能以残缺批次更新。若检查点已超过某轮而该轮结果缺失，程序会报错供人工检查，不会用新权重冒充旧轮模型。续训须保持同一源码、课程、种子及规则指纹；版本不符时明确拒绝。默认种子为 `20260930`。

这个入口需要 Python 环境、项目 Node 依赖及 CUDA 可用；无 CUDA 时会停止，避免误在 CPU 上启动长训练。测试可直接运行 `python -m unittest tests.test_ppo_rounds` 和项目原有 PPO 回归测试。
