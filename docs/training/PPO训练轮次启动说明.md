# PPO 轮次训练启动说明

> 此页记载此前 A/B 启动方式，现有 `PPO训练/启动PPO训练.cmd` 已改为 A1/A2 对照入口。当前操作方法见 [A1/A2 对照启动说明](PPO-A1-A2-对照启动说明.md)；以下 A/B 流程不再由该 CMD 自动执行。

双击仓库根目录 [PPO训练/启动PPO训练.cmd](../../PPO训练/启动PPO训练.cmd)。首次运行会在同一文件夹的 `.runtime/` 中准备本机 Node、pnpm 和 Python 训练环境，不依赖双击窗口的全局 PATH；若项目的 `node_modules` 尚未安装，会按锁文件安装。随后构建与当前源码指纹匹配的客户端和回放校验器，再询问目标总轮数 `x`。每轮为 10 次更新、每次更新 40 局完整训练对局。程序默认使用 **8 个持久环境和一份 GPU 模型**，先连续完成 A 课程的 `x` 轮，再完成 B 课程的 `x` 轮。输入 1 会分别训练 A、B 各 400 局；每轮另生成一局该轮模型的确定性贪心自我对打记录，不进入训练样本。运行时不会打开全屏窗口。本入口适用于客户端 v1.7.6；旧规则检查点不会自动迁移。

相同命令的非交互形式：

```powershell
& 'PPO训练/启动PPO训练.cmd' --rounds 1
```

执行前可仅检查计划，不开始训练：

```powershell
& 'PPO训练/启动PPO训练.cmd' --rounds 1 --dry-run
```

`PPO训练/A/第001轮/` 和 `PPO训练/B/第001轮/` 分别存放两套结果，后续轮次依次编号。原 `提交出牌实验` 下的已完成结果及检查点原样迁入这些目录；`outputs/ppo-training-v1.7.6/` 保留原样。旧版本权重不能直接续训新接口。每个轮次目录只有两个供查看的文件：

控制台使用单行进度显示：`A 第一轮 · 第一次更新 [####----------------] 8/40 20s`。数字表示当前更新已自然结束的完整对局数，不是决策数；全部 40 局结束后会短暂显示“优化中”。不再执行训练前的基线评估或每 10 次更新后的固定对手评估。每轮只额外生成一局自我对打记录。完整的更新指标仍保存在 `.state/<A或B>/training-report.json`，控制台不再打印大段 `updateSummary` JSON。

- `模型.pt`：该轮结束时的策略/价值网络权重及模型、课程、构建元数据；不含优化器，因此不能单靠它恢复训练。
- `AI训练记录.jsonl`：从主训练种子、课程和轮数派生一个独立随机种子，由该轮同一份模型控制六国完成一局自我对打。每步选模型概率最高的合法动作；种子仍决定环境随机事件。文件采用 `quartermaster-match-log / formatVersion=3`、`mode=resource_pool` 和 `quartermaster-training-scene/1.0.0`；开头的 `training.configuration.recordKind` 标注“AI训练记录”。一次已提交出牌及其目标、费用和子效果聚合成可读的 `training_action`，内部的预选和自动确认不另列动作；每条仍保存原序场面操作、卡牌移动及场面摘要。完整卡表、自然终局结果和模型/种子元数据随文件保存。导出时会运行协议解析和逐步场面重演；任一步不匹配则本轮结果不会发布。此文件可由支持训练回放适配器且场面规则指纹一致的游戏版本导入；它不是正式对局的出牌命令回放。

训练场不模拟 7 张真实手牌，因此回放中六国 `hand` 始终为空。尚未消耗的卡牌显示在 `drawPile`，已消耗的显示在 `discardPile`；出牌、费用和恢复等变化写成逐卡牌区移动。A 课程的 `resourcePool` 始终为空；B 课程在本国回合开始写入当轮开放卡牌，消耗后删除，并在下一次本国回合刷新。所有牌区都只是独立展示，不参与场面合法性重算。单独校验文件可运行：

```powershell
node scripts/validate-match-log.mjs "PPO训练/A/第001轮/AI训练记录.jsonl" --replay
```

`--replay` 会逐步重演场面与牌区；不带此选项只能验证格式与文件完整性。若导出失败，不会建立正式轮次目录；报错标出未能还原的动作。协议见 `docs/training-replay-output-v1.md`。

旧评估中的“40 局”来自固定 20 个种子各打两次（学习者分别控制轴心、同盟）；这一评估已取消，与每次更新仍需完成的 40 局自我对打训练批次无关。完整检查点和训练指标报告位于 `PPO训练/.state/A/`、`.state/B/`，不放进轮次目录，也不应发布到 Git。检查点包含模型、优化器、随机状态、累计训练量和规则指纹。

再次输入较大的目标总轮数会跳过当前实验已有完整轮次，从最新完整更新检查点继续；输入原轮数不会重复训练。旧 A 实验截至第 4 轮的成果与 `.state/A` 已单独归档至 `PPO训练/归档/A-20261002-截至第004轮/`，当前 A 结果及续训状态为空；双击入口会为 A 和 B 启动新实验，绝不自动加载归档。若进程在 40 局批次中途停止，只能从上一个完整更新边界重跑该批的相同任务；不能以残缺批次更新。若检查点已超过某轮而该轮结果缺失，程序会报错供人工检查，不会用新权重冒充旧轮模型。续训须保持同一源码、课程、种子及规则指纹；版本不符时明确拒绝。默认种子为 `20260930`。

首次环境准备从本机已有的 Codex 运行时复制 Node/pnpm，在 `.runtime/python/` 建立可调用本机 PyTorch 的虚拟环境；这台电脑已验证 CUDA 可用。`.runtime`、模型和记录都只保留在本地，不进 Git。基本牌继续使用牌＋目标完整动作；当前版本为 `ppo-actions-v4` / `ppo-observation-v5` / `ppo-vector-v5-repeat-build`，奖励配置增加 `repeated-basic-build-v1`。旧检查点语义不兼容，不能直接续训；原因和验证见 [重复建设第一阶段报告](PPO重复建设第一阶段-20261002.md)。若以后换电脑且缺少上述本机运行时，准备脚本会明确报缺失项；无 CUDA 时会停止，避免误在 CPU 上启动长训练。测试可运行 `python -m unittest tests.test_ppo_rounds tests.test_ppo_repeat_build` 和项目原有 PPO 回归测试。
