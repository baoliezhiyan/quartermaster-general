# PPO 轮次训练启动说明

双击仓库中的 `scripts/启动PPO训练.cmd`，输入目标总轮数 `x`。每轮为 10 次更新、每次更新 40 局完整训练对局。程序默认使用 **10 个持久环境和一份 GPU 模型**，先连续完成 A 课程的 `x` 轮，再完成 B 课程的 `x` 轮。输入 1 会分别训练 A、B 各 400 局；固定种子的评估局及每轮抽样记录局另计，不进入训练样本。运行时不会打开全屏窗口。

相同命令的非交互形式：

```powershell
python -m scripts.ppo_rounds --rounds 1
```

执行前可仅检查计划，不开始训练：

```powershell
python -m scripts.ppo_rounds --rounds 1 --dry-run
```

结果存于 `outputs/ppo-training/A/第001轮/` 和 `outputs/ppo-training/B/第001轮/`，后续轮次依次编号。每个轮次目录只有两个供查看的文件：

- `模型.pt`：该轮结束时的策略/价值网络权重及模型、课程、构建元数据；不含优化器，因此不能单靠它恢复训练。
- `AI训练记录.jsonl`：在固定的 20 个评估种子中随机选一个，再随机选学习者阵营，使用该轮模型对战同一冻结规则对手。日志以“AI训练记录”开头，逐次保存选择和完整竞技场状态快照，结尾记录自然终局、分数、决策数和摘要。它是训练专用记录，**当前不能直接导入正式游戏回放**；待正式回放协议确定后再适配。

每轮训练后仍按既定评估协议，对固定 20 种子分别由学习者扮演轴心和同盟，共 40 局；评估指标放在内部报告中，与抽样可读日志分开。完整检查点和评估报告位于 `outputs/ppo-training/.state/A/`、`.state/B/`，不放进轮次目录，也不应发布到 Git。检查点包含模型、优化器、随机状态、累计训练量和规则指纹。

再次输入较大的目标总轮数会跳过已有完整轮次，从最新完整更新检查点继续；输入原轮数不会重复训练。若进程在 40 局批次中途停止，只能从上一个完整更新边界重跑该批的相同任务；不能以残缺批次更新。若检查点已超过某轮而该轮结果缺失，程序会报错供人工检查，不会用新权重冒充旧轮模型。续训须保持同一源码、课程、种子及规则指纹；版本不符时明确拒绝。默认种子为 `20260930`。

这个入口需要 Python 环境、项目 Node 依赖及 CUDA 可用；无 CUDA 时会停止，避免误在 CPU 上启动长训练。测试可直接运行 `python -m unittest tests.test_ppo_rounds` 和项目原有 PPO 回归测试。
