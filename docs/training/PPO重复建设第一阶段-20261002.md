# PPO 重复建设第一阶段修正与诊断（2026-10-02）

范围仅为 A/B 资源池训练竞技场及 PPO 奖励。正式客户端规则、计分、候选合法性、观察字段、网络结构、熵系数 0.01、原有势函数/终局奖励、优势和 PPO 参数均不变。本阶段不启动长训练。

## 发现与修正

基本建设的完整候选已有 `choices[0].regionId`，观察的 `units` 也包含国家、兵种与地区，状态编码逐单位写入这些信息。但 `sourceCandidates()` 在从引擎的 `BasicOption.existingId` 生成完整候选时漏传 `repeated`；`choiceCandidates()` 对分步结算的同类计划则已经传递它。Python `Encoder.encode_candidate()` 会编码该字段，因此实际送进网络的基本建设候选把“在已有本国同类部队地区重复建设”编码成了普通建设。现在补齐 `repeated: !!option.existingId`，不增加张量维度或新观察字段，观察语义升级至 v5。

事件效果编码已经遍历完整的 `effects` 序列，包括每个动作、候选地区及其余子效果；没有只编码第一个子动作。事件中后续必须依据实际结算局面选择的目标依旧在对应时点决策。当前修正不提前固定它们。

## 训练奖励与统计

在 `PpoTrainingArena.step()` 提交 `PLAY_BASIC` 后确认完整出牌结果。仅对**单一建设动作、没有场上持续效果、确为原地重复、牌已完成结算、出现真实 `UNIT_PLACED.repeated`、没有部队或摸牌堆等其他效果变化**的基本牌继续判断；当行动开始时同一观察里另有能实际新增部队的库存基本建设候选，向该次决策增加 -0.01 训练奖励。合法重复建设仍消耗牌与出牌机会，游戏分数不改。不能确认无附加效果、未完成、没有有效替代的情况豁免；事件牌、得分牌、攻击后受防御/反制、费用/回收复杂行动本阶段均不进入惩罚判定。有效替代仅可靠核验当前课程的库存基本建设，不递归模拟全部事件候选。

`decision_rewards()` 先按原有阵营奖励计算，再只对 `wasteCheck.seat == previous.decisionSeat` 的发起者阵营加一次 -0.01；对手没有对称正奖励，也不把惩罚附到下个国家。对局轨迹按原决策索引保存，原有回合时间折扣与 `assign_advantages()` 不变。报告新增重复基本建设、原因、按国家惩罚次数和总惩罚额；`shaped` 保留原奖励，`trainingReward` 单列加入惩罚后的值。日志中的游戏分数与训练奖励仍分开。
