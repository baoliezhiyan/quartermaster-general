# 下一步：并行竞技场与40局完整批次

状态：用户已明确的开发要求；是否实现以对应PR和验收为准。本文件覆盖PPO v0.3中约4096决策结束采集的条件，其他奖励、优势计算、合法性和课程规则不变。

- 一批固定40局，预先分配任务/种子，每局恰好一次；同一批策略冻结。环境提前结束可以领取本批剩余任务，不能多开第41局。
- 全部40局自然结束后，分别按局、按决策国家计算优势，再统一PPO更新。不得把未完成局留到新策略下继续；异常截断停止本批更新并诊断。
- 首轮计划50次更新=2000训练局；训练前及每10次更新做固定20种子×两个阵营的40局评估，评估局不训练。正式长训须等用户确认，优化任务只运行必要短基准。
- 一个GPU模型/优化器，多个持久环境。按实测决定逐个或动态小批量推理，不能为凑批等待所有环境；至少测1/5/10环境完整端到端速度和内存。
- 允许训练专用规则执行路径，与正式客户端实现分离，但以同种子/动作序列逐步对比状态、候选、随机与结算时点证明等价，不能减少必要触发检测。
- 优先触发来源索引、地图依赖缓存、静态特征/输入编码、重复探测与复制；性能提升不能靠丢失观察或动作语义。
- 逐局随机流与任务绑定，动作响应带环境/对局/决策/策略版本标识。更新期间无在途旧策略任务。
- 至少保存完整更新边界检查点；若支持采集中途恢复，保存全部环境/轨迹/任务和随机状态。否则明确只能回到上次更新，不能使用残缺批次。
- 固定40局不等于每局梯度等权：本轮继续按有效决策样本计算PPO损失，不额外引入逐局重加权。
- 对照组A/B独立训练；不能未经讨论改奖励、胜负条件或混用课程。普通采集日志与抽样完整回放分开。
