# v1.6.1 场景锁定、本地客户端与传输优化

## 实现边界

- 场景锁保存在 Room 中，排队请求处理时检查，非 GM 游戏命令和回退在引擎执行前拒绝。读请求、在线状态、座位管理不改变局面。GM 可继续编辑。离席/断线自动释放。不改变存档、回放或卡牌结算规则。
- 本地客户端仅监听 127.0.0.1，静态文件从本包 dist 读取；只转接 `/api/identity`、`/api/request`、`/api/socket` 到启动时指定的固定房主。校验本机 Host/Origin，转接时只传必要 JSON/身份头，不转发浏览器 cookie，不提供任意目标代理。
- 主机仍执行相同权限投影与增量同步，本地客户端不能获取额外国家信息。直连与本地加入共享身份/房间接口。
- 本机与房主核对整个 dist 内容指纹，不能仅凭版本号判断兼容性。房间持久化 room-id 用于本地身份隔离；公网入口变了但房间数据保留时仍可复用身份。重连再次核对指纹，临时网络失败允许浏览器自动重试。
- 静态文件启动时建立内存内容/哈希表；请求不重复读盘、计算哈希。入口 HTML 和 API 不缓存；带正确内容哈希的卡图、构建的哈希 JS/CSS 一年 immutable；其他文件 ETag/no-cache，可 304 校验。跨公网域名的浏览器缓存限制并未被取消，本地客户端不依赖跨域复用。

## WebSocket 测量

脚本：`node scripts/measure-ws-compression.mjs`。结果：`outputs/client-localization/compression.json`。

从四组真实游戏局面（短/长对局 × 建陆/空军操作）收集六国和 GM 的完整快照、操作增量、回退，共 168 条消息。用真实 ws 协商压缩并逐条核对解压内容完全相同，统计服务端 socket 写入字节。7 轮交错测量，排除首轮预热，以下为中位数。CPU 包含发送端压缩和接收端解压，Windows CPU 计时粒度较粗，不能据此判断 level 3 比 level 1 更省 CPU。

| 模式 | 总线缆字节 | 本机整批耗时 | 整批 CPU |
|---|---:|---:|---:|
| 不压缩 | 1,989,273 | 14.64 ms | 15 ms |
| level 1，≥4096 B | 433,620 | 25.56 ms | 47 ms |
| level 3，≥4096 B | 428,473 | 26.43 ms | 32 ms |

采用 level 1：比不压缩少 78.2% 字节，level 3 只再少约 1.2%。在 1 Mbps 有效吞吐且这些消息串行占用链路的简化模型下，整批纯传输时间约 15.9 秒降为 3.5 秒；这不是一次出牌耗时，也不包含网络 RTT、隧道、排队。实测为本机测试，没有声称测过真实公网延迟。

低于 4 KiB 的消息不压缩，关闭上下文复用，最多四项 zlib 并发；不支持协商的客户端仍能接收原文。本地客户端连接房主时协商压缩，本地浏览器段不重复压缩。
